# v1.20.0 — Thread Description: описание и сводка каждого треда

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Новый плагин **Thread Description**: у названия каждого треда и подтреда круглая
  «i» с описанием, о чём тред; в правом верхнем углу поля ввода — иконка со сводкой
  «где мы сейчас и что дальше». Карточка открывается по наведению, клик её закрепляет.
- Описание пишется по первой задаче; короткая задача уточняется после первого ответа
  агента; дальше текст обновляется не чаще раза в час и только когда открывают карточку.
- Тексты пишет скрытый служебный тред на машине треда (Claude Haiku или другая
  доступная модель). Одна генерация — около 42 тыс. токенов; `bb thread-description stats`
  показывает расход по дням.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `plugin-thread-description` — Thread Description 0.1.0: описание и сводка каждого треда

Устанавливает на сервере BB новый плагин Thread Description 0.1.0. Штатный шаг
`local-plugin` собирает и ставит плагин из `plugins/thread-description` и
проверяет источник и версию.

У названия каждого треда появляется иконка с описанием, в углу поля ввода — иконка
со сводкой; обе показывают карточку по наведению. Описания создаются сами по первой задаче и обновляются не чаще раза
в час, когда открывают карточку. Генерация — обычный запрос к провайдеру на машине треда
(по умолчанию Claude Haiku, при отсутствии — другая доступная модель) и
расходует его лимит; выключается настройкой `enabled`.

Проверка: `bb thread-description models --thread <id>` показывает, чем будет
создано описание, `bb thread-description refresh --thread <id>` создаёт его.
