Тред на «Каскаде подписок» знает о себе через окружение CLI ступени (`BB_CASCADE_PROFILE`, `BB_CASCADE_STEP`), промпт не меняется — кэш промптов сохраняется. Подтреды запускаются через каскад с профилем родителя; просьба «Codex 6.2 на Tru», «на аккаунте vclaude» разбирается командой `bb subscriptions-cascade resolve` в закреплённую ступень, кандидатов или запасной путь со штатным провайдером. В списке моделей после профилей — закреплённые ступени «Tru · Codex · GPT-6.2 Sol», «Mac · Claude (vclaude) · Opus 5.5» (только включённые ступени и доступные модели, не больше 64 пунктов); смена на «Авто» продолжает ту же сессию.
На чужой ступени CLI видит свой тред: `bb status` и `bb thread show` работают на Mac и UA. Codex на ступени получает штатную песочницу и сеть, как обычный тред Codex. Треды одной папки на одной машине пишут одновременно, ход на Tru не ждёт исполнителя; тред с третьей машины идёт на машину писателя или ждёт со строкой «Жду: папку держит тред …». Долгая подготовка хода больше не обрывается через 300 с («fetch failed»). У ступени есть лимит одновременных ходов (`maxConcurrent`, «ждать места» или «следующая ступень»). `adopt --native --thread <id>` переводит тред Claude Code на каскад с той же сессией (сначала `--dry-run`; живые треды без согласия владельца не переводить).
Откат: тег agentcli-subscriptions-cascade/v0.2.16.
