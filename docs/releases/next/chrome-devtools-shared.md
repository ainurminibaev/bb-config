### `chrome-devtools-shared` — Chrome для агентов без повторных запросов

Выполняется на каждой macOS-машине-исполнителе, где Codex использует
chrome-devtools-mcp. Зависимостей нет. На других ОС `--check` и `--apply`
сообщают «Неприменимо» и ничего не меняют. Это новый необязательный компонент:
спросите пользователя, работают ли агенты с его основным Chrome.

Применён, если `python3 scripts/chrome_devtools_shared.py --check` печатает `OK`.
Проверка не подключается к Chrome и диалога не вызывает.

`--apply` под пользователем, запускающим Codex, делает следующее:
- ставит закреплённый chrome-devtools-mcp в `~/.local/share/chrome-devtools-mcp-shared`;
- ставит mcp-proxy 0.15.0 через `uv tool install`;
- создаёт LaunchAgent `dev.bb-config.chrome-devtools-mcp-shared` (127.0.0.1:8766);
- в `~/.codex/config.toml` (или `$CODEX_HOME`) заменяет только таблицу
  `[mcp_servers.chrome-devtools]` на `url = "http://127.0.0.1:8766/mcp"`.

Прежний файл и прежняя запись сохраняются в `backup/`. Пути вычисляются от
домашнего каталога, Node.js ≥ 20.19 ищется автоматически, нужен uv.

После применения: если в Chrome не включено `chrome://inspect/#remote-debugging`,
пользователь включает его сам. При первом обращении агента он один раз нажимает
«Allow». Агент нажимать не должен: это решение пользователя. Открытые сессии
Codex надо перезапустить, работающие ходы не прерывать.

Ожидаемый результат: новые сессии Codex видят вкладки основного Chrome без
нового диалога, пока Chrome и служба работают. Повтор после прерывания безопасен,
начинайте с `--check`. Откат — `--remove`. Каталог службы и mcp-proxy остаются.
