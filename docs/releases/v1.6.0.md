# v1.6.0 — Дома плагинов, Shared Guides, Browser Relay и Codex Delegation Watch

Общий порядок — [docs/updates.md](../updates.md). Состав — [docs/components.md](../components.md).

## Что изменилось

- **Дома плагинов.** У каждого плагина один «дом»: bb-config, отдельный проект
  или «не отслеживать» (`config/plugin-homes.json`, `scripts/plugin_scope.py`).
  Snapshot и restore учитывают дом; о новом плагине без дома агент спрашивает
  один раз. Прежний список `externally-managed-plugins.json` продолжает работать.
- **Shared Guides 0.1.0** (новый компонент набора): короткие общие инструкции BB
  ссылаются на навыки bb-config-tracking, thread-transfer и agent-compat.
- **Codex Delegation Watch 0.2.0** (новый компонент набора): у делегированного
  треда Codex первой строкой задаётся цель, надзор проверяет его каждые 5 минут;
  настройки и экран надзора.
- **Browser Relay**: агенты на любой машине работают в Chrome пользователя через
  одно подключение, без повторных «Allow remote debugging?». Плагин ставится из
  отдельного репозитория; заменяет невыпущенную службу chrome-devtools-shared.
- **Claude Code: CLAUDE.md только как импорт `@AGENTS.md`** — хук не даёт писать
  правила в CLAUDE.md, они пишутся в AGENTS.md.
- **Plugin Keeper 0.2.10**: исправление Tokenomics теперь накладывает Keeper;
  исправления, вошедшие в каталожный релиз плагина, отключаются сами, отключённые
  правила сохраняются.
- **Project Logo 0.2.2**: навык виден агентам (дубль project-logos убран).
- **Config Updates 0.3.1**: описание плагина соответствует кнопке «Обновить».

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `browser-relay` — Browser Relay: Chrome пользователя для агентов с любой машины без повторных «Allow remote debugging?»

Агенты на любой машине (в том числе Codex на серверах) работают в настоящем Chrome
пользователя через одно общее подключение: `bb browser-relay call <инструмент>`.
Chrome спрашивает «Allow remote debugging?» один раз после запуска, а не на каждого агента.

Плагин ставится из отдельного репозитория `bb-plugin-browser-relay` и сам ставит
службу на Mac (`bb browser-relay service install --machine <Mac>`). Прежняя служба
chrome-devtools-shared из bb-config (любая метка) переносится автоматически — Chrome
один раз спросит «Allow». Codex на том же Mac продолжает работать через MCP
`chrome-devtools`, указывающий на ту же службу.

Заменяет невыпущенный шаг `chrome-devtools-shared`.

На машине, где службы раньше не было, её ставят вручную одной командой —
шаг сам машину с Chrome не выбирает.

### `claude-md-guard` — Claude Code: CLAUDE.md — только импорт @AGENTS.md, правила пишутся в AGENTS.md

Ставит в Claude Code на уровне пользователя хук `PreToolUse`: запись в
`CLAUDE.md` чего-либо, кроме строк-импортов вида `@AGENTS.md`, отклоняется с
подсказкой писать правила в `AGENTS.md`, который читают все агенты. Правки,
убирающие старое содержимое, разрешены. Другие хуки не меняются.

Проверка: `python3 scripts/claude_md_guard.py --check`. Удаление: `--remove`.

### `plugin-config-updates-description` — Config Updates 0.3.1: описание плагина про кнопку «Обновить»

Описание плагина в Settings → Installed plugins говорит о выборе компонентов и
обновлении кнопкой вместо прежнего «запускает применение агентом».

### `plugin-homes` — Общие инструкции: дома плагинов (спросить один раз) и блок «совместимость агентов»

У каждого плагина BB теперь один «дом»: `config/plugin-homes.json` (и личный
`.local/config/plugin-homes.json`) сопоставляет ID плагина с `bb-config`,
`project` (плагин из репозитория проекта и команда его установки) или `ignore`.
Старый `config/externally-managed-plugins.json` читается как `ignore`.

Snapshot и restore не копируют код и настройки плагинов `project`/`ignore`;
restore ставит `project`-плагин командой из checkout'а его проекта или
пропускает с сообщением, если проекта на машине нет. `snapshot.py --check`
перечисляет установленные плагины без дома.

Шаг обновляет текст уже включённого напоминания «bb-config tracking» и добавляет
блок «agent compatibility» (правила в AGENTS.md, CLAUDE.md = `@AGENTS.md`, подробности —
навык agent-compat плагина Shared Guides): агент
один раз спрашивает, где хранить новый плагин, и записывает ответ командой
`python3 scripts/plugin_scope.py set …`. Если напоминание не включено, шаг
ничего не меняет.

Проверка: `python3 scripts/setup_tracking.py --check`,
`python3 scripts/plugin_scope.py show`. Формат — docs/customizations.md,
раздел «Дома плагинов».

### `plugin-keeper-record-retirement` — Сохранение отключённых правил Plugin Keeper

При отключении правила Plugin Keeper проверяет приватный снимок настроек,
записывает версию апстрима в bb-config и создаёт локальный коммит. При
занятых файлах сохраняет патч и указывает его в уведомлении.

### `plugin-keeper-tokenomics` — Plugin Keeper для Tokenomics

Plugin Keeper проверяет включённый каталоговый Tokenomics после обновлений. Неизвестный размер окна преобразуется в JSON null. При несовпадении якоря отображается предупреждение.

### `plugin-keeper-upstream-retirement` — Автоотключение исправлений Plugin Keeper

Plugin Keeper сверяет исходники установленной каталожной версии с правилами
совместимости. Если автор выпустил исправление, Keeper отключает правило и
один раз уведомляет настроенный тред. Правило можно включить через `forceRules`.

### `plugin-project-logo-skill` — Project Logo 0.2.2: навык виден агентам, в том числе для явной просьбы поставить или заменить логотип

Project Logo 0.2.2. Навык `project-logo` раньше не доходил до агентов: плагин
передавал BB пустой список навыков. Теперь навык доступен во всех тредах
обычных проектов. После автоматической проверки значка инструменты скрыты, а
навык остаётся и описывает явную просьбу «поставь/замени логотип проекта»
через `bb project-logo` и ручную замену `.bb/icon.*`.

Проверка: в новом треде обычного проекта среди навыков есть `project-logo`.

### `plugin-shared-guides` — Shared Guides 0.1.0: навыки к коротким общим инструкциям (bb-config, перенос треда, совместимость агентов)

Устанавливает на сервере BB плагин Shared Guides 0.1.0 — только навыки, без
интерфейса и инструментов: `bb-config-tracking`, `thread-transfer`,
`agent-compat`. Общие инструкции BB (Custom instructions)
держат короткие триггеры «когда и что», а порядок действий загружается из этих
навыков по требованию.

Проверка: `bb skill list` показывает три навыка с источником plugin.
