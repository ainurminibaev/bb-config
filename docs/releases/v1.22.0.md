# v1.22.0 — Каскад подписок 0.3.2 и аккаунты VClaude по машинам

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- **Каскад подписок 0.3.2.** Подтреды треда на каскаде тоже запускаются через каскад с профилем
  родителя. В списке моделей появились закреплённые ступени вида «машина · CLI · модель». Просьбу
  «Codex на Tru» или «на аккаунте vclaude» разбирает команда `bb subscriptions-cascade resolve`.
  Тред узнаёт о каскаде из окружения CLI (`BB_CASCADE_PROFILE`, `BB_CASCADE_STEP`), промпт не
  меняется, поэтому кэш промптов сохраняется.
- На чужой ступени работают `bb status` и `bb thread show`. Codex получает штатную песочницу и
  сеть. Несколько тредов одной папки пишут на одной машине одновременно, долгая подготовка хода
  больше не обрывается с «fetch failed». У ступени есть лимит одновременных ходов (`maxConcurrent`).
- Машину можно убрать из каскада: каскад сам закроет её блокировку писателя и вернёт правки на опору.
- Фоновые субагенты и фоновые команды на чужой ступени доживают до конца и возвращают итог в тред.
- `adopt --native` переводит тред Claude Code на каскад с той же сессией. Сначала запускайте
  `--dry-run`, а живые треды переводите только с согласия владельца.
- **Thread Account Usage 0.3.2.** Аккаунты VClaude различаются по машинам: у каждого почта
  кабинета или ручная метка (`vclaudeLabels`) и свой значок. Под строкой аккаунта перечислены его
  машины. Ключ шлюза машину не покидает, сервер получает только короткий хеш.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `subscriptions-cascade-0-3-0` — Каскад подписок 0.3.2 — подтреды через каскад, закреплённые ступени, resolve, adopt --native, лимит ходов на ступени, уход машины из каскада, фоновые субагенты доживают

Тред на «Каскаде подписок» знает о себе через окружение CLI ступени (`BB_CASCADE_PROFILE`, `BB_CASCADE_STEP`), промпт не меняется — кэш промптов сохраняется. Подтреды запускаются через каскад с профилем родителя; просьба «Codex 6.2 на Tru», «на аккаунте vclaude» разбирается командой `bb subscriptions-cascade resolve` в закреплённую ступень, кандидатов или запасной путь со штатным провайдером. В списке моделей после профилей — закреплённые ступени «Tru · Codex · GPT-6.2 Sol», «Mac · Claude (vclaude) · Opus 5.5» (только включённые ступени и доступные модели, не больше 64 пунктов); смена на «Авто» продолжает ту же сессию.
На чужой ступени CLI видит свой тред: `bb status` и `bb thread show` работают на Mac и UA. Codex на ступени получает штатную песочницу и сеть, как обычный тред Codex. Треды одной папки на одной машине пишут одновременно, ход на Tru не ждёт исполнителя; тред с третьей машины идёт на машину писателя или ждёт со строкой «Жду: папку держит тред …». Долгая подготовка хода больше не обрывается через 300 с («fetch failed»). У ступени есть лимит одновременных ходов (`maxConcurrent`, «ждать места» или «следующая ступень»). `adopt --native --thread <id>` переводит тред Claude Code на каскад с той же сессией (сначала `--dry-run`; живые треды без согласия владельца не переводить).
Машину можно убрать из каскада (или выключить): её оставшийся выход писателя каскад закрывает сам — правки возвращаются на опору, а если машина недоступна, через 5 минут блокировка снимается со строкой, где могли остаться правки; gc собирает её реплики. Подтред, у которого машина родителя ушла из каскада, идёт по профилю, а отказ «нет ступеней» называет причину по каждой ступени (0.3.1).
Фоновые субагенты и фоновые команды CLI на чужой ступени доживают и возвращают итог в тред: CLI не отпускается, пока они идут, их запросы разрешения доходят до BB (0.3.2).
Откат: тег agentcli-subscriptions-cascade/v0.2.16.

### `thread-account-usage-vclaude-accounts` — Thread Account Usage 0.3.2 — аккаунты VClaude по машинам: подпись почтой или меткой, логотип, машины по аккаунту

Аккаунты VClaude различаются по машинам.

**Аккаунт машины.** Машина сообщает серверу BB короткий ID аккаунта VClaude —
первые 8 символов sha256 ключа шлюза (`ANTHROPIC_AUTH_TOKEN` или
`ANTHROPIC_API_KEY` из `env` в `~/.claude/settings.json`, иначе из окружения).
Сам ключ машину не покидает и нигде не хранится. Машины с одним ключом — одна
строка, под ней список машин.

**Подпись и логотип.** В «Все аккаунты», на странице «Аккаунты и объёмы» и в
шапке треда вместо общего «VClaude» стоит почта кабинета или ручная метка, со
своим значком VClaude (простая «V», не логотип сервиса). Почта берётся из
ответа кабинета, если он её сообщает, иначе из входа кабинета на сервере BB
(`login.json`, только поле email). Ручная метка — настройка плагина
`vclaudeLabels`: JSON `{"<ID>": "<метка>"}`; ID виден в подсказке строки
(«VClaude · <ID>»).

**Несколько аккаунтов.** Кабинет на сервере BB один. Его остаток относится к
единственному ключу, а при нескольких ключах — к тому, чья метка равна почте
кабинета. Остальные аккаунты показаны своими строками с машинами и пометкой
«Кабинет этого аккаунта не подключён»; без сопоставления остаток кабинета —
отдельной строкой без машин. Машины со сборкой хоста старше 0.3.2 (без ID)
остаются под строкой кабинета, как раньше.

**Шапка треда VClaude** — подпись аккаунта той машины, где идёт ход (и для
ступени каскада через VClaude).

Один аккаунт выглядит как раньше, плюс подпись и значок. Откат: тег
thread-account-usage/v0.3.1.

  покрыто тестами.
