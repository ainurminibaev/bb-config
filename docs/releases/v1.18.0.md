# v1.18.0 — Обновление больше не застревает на плагинах со своими тегами

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Обновление с версий до v1.13.0 больше не застревает. Шаги v1.12.0 ждали
  плагины «из папки выпуска», а с v1.13.0 и v1.15.0 эти плагины ставятся из
  своих Git-тегов `<id>/vX.Y.Z`; проверка падала («the pinned release build is
  not installed»), и уведомление «Доступно обновление доработок BB» не уходило.
  Теперь такой шаг принимает плагин из его собственного тега, если версия не
  старше нужной, а иначе просит `bb plugin update <id>`.
- Только исправление механизма обновлений; плагины и настройки не меняются.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

## Проверка релиза

Из чистого клона коммита выпуска: `python3 scripts/updates.py validate v1.18.0`,
`python3 -m unittest discover -s scripts -p 'test_*.py'` (новая проверка в
`test_updates.py`: тег своего плагина принимается, более старая версия и
чужой тег — нет), `python3 scripts/privacy_check.py --history`. На установке
автора застрявшее обновление v1.11.0 → v1.17.0 доходит до v1.18.0.
