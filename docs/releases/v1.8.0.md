# v1.8.0 — PR и Issues, Fresh Thread Hint, Limit Guard, Machine Tabs, Project Catalog

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Новый плагин «PR и Issues» 0.4.0: страница в боковом меню с вашими PR и
  issue на GitHub — что ждёт вашего действия, что ждёт других, что закрыто,
  лента изменений и экран «Источники» (организации и репозитории: Всё / Моё /
  Скрыть). Список по репозиториям, записи подгружаются страницами; скинутая
  запись возвращается при любом обновлении на GitHub. Нужен вход `gh` на
  сервере BB.
- Новый плагин Fresh Thread Hint 0.1.1: над полем ввода появляется подсказка
  продолжить большой давно молчащий тред Claude в новом.
- Новый плагин Limit Guard: агенты видят остаток лимита подписки, у порога
  работают короткими законченными шагами, при обрыве хода сохраняется снимок
  незаконченной работы.
- Machine Tabs 0.2.5: меню проектов в поле «Поиск тредов»; с 0.2.4 в строке
  треда видны значки других плагинов.
- Project Catalog 0.7.0: синхронизация папки при старте треда, отдельная
  копия для второго треда в занятой папке, история и worktree-копии.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `plugin-fresh-thread-hint` — Fresh Thread Hint 0.1.1: подсказка продолжить в новом треде, когда большой тред Claude остыл

Устанавливает на сервере BB новый плагин Fresh Thread Hint 0.1.1. Штатный шаг
`local-plugin` собирает и ставит плагин из `plugins/fresh-thread-hint` и
проверяет источник и версию.

Над полем ввода большого треда Claude Code, который простоял больше часа,
появляется одна строка: та же задача — оставайтесь здесь, новая — лучше
продолжить в новом треде. Кнопка «Продолжить в новом» открывает штатную панель
Handoff (нужен включённый плагин `handoff`), «?» объясняет, почему сообщение в
остывший тред дорогое и на сколько процентов дешевле новый тред, «×» скрывает строку до следующей активности треда.
Плагин не отправляет сообщений и не хранит данных на сервере. Пороги
(150 тыс. токенов и 60 минут) меняются через `bb plugin config`.

Проверка: откройте тред Claude с контекстом больше 150 тыс. токенов,
простоявший больше часа, — над полем ввода есть строка, по «?» открывается
объяснение, кнопка открывает панель Handoff. В маленьком или только что
работавшем треде строки нет.

### `plugin-limit-guard` — Limit Guard: агенты видят остаток лимита и сохраняют работу маленькими шагами

Новый плагин Limit Guard. Работа не теряется, когда лимит подписки кончается
посреди хода.

- **Снимки незаконченной работы делает плагин.** Это коммит состояния папки
  под `refs/wip/bb/<окружение>`; файлы, ветка и индекс не меняются.
  - Для папок без git — теневой репозиторий на той же машине.
  - Когда: прерванный ход, режим финиша, затихший тред с правками, архивация
    worktree.
  - По умолчанию снимок остаётся на машине. Отправку на сервер можно
    включить (`snapshots push-private`): только в приватный репозиторий и
    без похожих на секреты файлов.
- **Сообщение в идущий ход** Claude Code и Codex, когда режим ухудшился.
  Пороги: 5 часов — 75/90% или по темпу; неделя и окно модели — 90/97%.
- **Правила агенту:** ради лимита не коммитить; коммиты — только законченные
  шаги и свои файлы.
- **Застрявший тред:** уведомление, если ждать долго или автоповтора нет;
  предложение другой модели или сервиса (`bb limit stuck`). После
  `bb handoff` автоповтор исходного треда снимается.
- **Неприоритетные треды:** `bb limit priority low|background|normal`;
  задания ждут, пока окно выше порога, который растёт к сбросу окна
  (5 ч 40→90%, неделя и окно модели 60→95%).
- **Продолжение после сброса:** в финише агент ставит в очередь треда строку
  «продолжай» на момент сброса окна (`limit_resume_after_reset`,
  `bb limit resume`); тред продолжит сам.
- **Выключатели:** файл `.bb/hands-off` в папке,
  `bb plugin config limit-guard set snapshots off`,
  `bb plugin disable limit-guard`.

Проверка на сервере BB:

```sh
bb plugin list | grep limit-guard
bb limit status --thread <id треда Claude или Codex>
bb limit snapshot --thread <id>
bb limit snapshots
bb limit stuck
```

Правила попадают в сессию агента при её следующем запуске; уже работающие
треды получат их после перезапуска (`bb thread stop`, история сохраняется).

Заменяет отдельный плагин `low-priority`: если он стоит, удалите его (`bb plugin uninstall low-priority`).

### `plugin-machine-tabs-project-menu` — Machine Tabs 0.2.5: меню проектов в поле поиска

Machine Tabs 0.2.5 добавляет меню проектов в поле «Поиск тредов». Кнопка-папка
появляется при наведении на поле, рядом с воронкой. Наведение на неё показывает
компактный список проектов: поиск, быстрые фильтры (работают, ждут ответа,
ошибки, новое) и проекты по последней активности со счётчиками статусов тредов.
Щелчок по проекту прокручивает боковую панель к нему и подсвечивает группу.
Стрелка у проекта показывает его треды со статусами; щелчок открывает тред и
подсвечивает его в списке.

Проверка: `bb plugin list | grep machine-tabs` показывает 0.2.5; при наведении на
поле поиска рядом с воронкой видна кнопка-папка.

### `plugin-machine-tabs-row-marks` — Machine Tabs 0.2.4: значки других плагинов в строке треда

Machine Tabs 0.2.4 показывает в строке треда значки, которые добавляют другие
плагины через `experimental_threadRowMetadata`: например, серую стрелку вниз
неприоритетного треда из Limit Guard, на паузе — стрелку с паузой. Значки стоят
справа от названия, рядом со статусом треда. Если ни один плагин значка не
даёт, строка не меняется.

Проверка: в боковом списке у неприоритетного треда видна стрелка вниз;
`bb plugin list | grep machine-tabs` показывает 0.2.4.

### `plugin-pr-issues` — PR и Issues 0.4.0: страница в боковом меню с вашими пулреквестами и issue на GitHub

Устанавливает на сервере BB новый плагин «PR и Issues» 0.4.0. Штатный шаг
`local-plugin` собирает и ставит плагин из `plugins/pr-issues` и проверяет
источник и версию.

В боковом меню появляется страница «PR и Issues»: ваши PR и issue на всём
GitHub, запросы вашего ревью, упоминания и все записи в организациях и
репозиториях, включённых на экране «Источники» (Всё / Моё / Скрыть). Разделы «Нужно ваше действие», «Ждут других», «Завершённые» и
«Лента изменений»; статусы простыми словами («Просят изменения», «Принят
(влит)», «Отклонён»), точка «новое», значок с числом записей, где ход за вами.
С записью можно: открыть на GitHub, прокомментировать, закрыть, открыть заново,
влить, одобрить (с подтверждением), скрыть до нового ответа, поручить агенту в
новом треде. Нужен `gh`, залогиненный на сервере BB (`gh auth status`).

Проверка: `bb prs refresh` печатает числа по разделам; в боковом меню есть
«PR и Issues», страница открывается и показывает записи.

### `plugin-project-catalog-sync` — Project Catalog 0.7.0: синхронизация при старте, изоляция второго треда, история и worktree-копии

Project Catalog 0.7.0 синхронизирует папку проекта перед работой, показывает
worktree-копии и изолирует второй тред в занятой папке.

- **Первое сообщение треда** ненадолго встаёт в очередь («Синхронизирую папку
  проекта»). Плагин делает `git fetch` и подтягивает свежее — **только
  fast-forward чистой папки**, где никто больше не работает и нет файла
  `.bb/hands-off`. Затем сообщение уходит, итог — в инструкциях агента.
  Настройка `autoPull`: `auto` / `check` / `off`. Вручную: `project_sync`
  или `bb catalog pull [--check]`.
- **Занятая папка.** Если там уже работает другой тред, агент до правок
  вызывает `project_isolate` и работает в своей копии (git worktree на своей
  ветке). Закоммиченное плагин вольёт обратно сам, когда основная папка
  освободится; при конфликте ничего не меняет и сообщает.
- `bb catalog history` и блок «Синхронизация» в карточке; `bb catalog
  worktrees` и блок «Worktree»: размер и состояние копий, забытые — первыми.
- Каждые 30 минут — fetch активных за неделю проектов (только сведения о
  сервере). Удаление записей о worktree без папки — только если включить
  `cleanupMissingWorktrees`.

Проверка на сервере BB:

```sh
bb plugin list | grep project-catalog
bb plugin config project-catalog
bb catalog pull --check --thread <id треда проекта>
bb catalog history <проект>
bb catalog worktrees
```

  `python3 scripts/privacy_check.py --history`.

  `bb plugin list --json`: pr-issues 0.4.0, fresh-thread-hint 0.1.1,
  limit-guard, machine-tabs 0.2.5, project-catalog 0.7.0.
