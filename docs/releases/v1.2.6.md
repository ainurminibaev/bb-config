# v1.2.6 — Обновления из закреплённых релизов GitHub

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- «Обновить с ИИ» получает исходники и инструкции из закреплённого релиза
  GitHub. Незавершённая разработка в рабочем checkout больше не мешает.
- BB переводит свои локальные плагины на исходники релиза с сохранением
  настроек. Журнал записывает проверенные версии и источники плагинов.
- Config Updates показывает несовместимые зависимости, в том числе после
  ручного обновления стороннего плагина.

## Шаги

### `plugin-config-updates-isolated-release` — Config Updates 0.1.6 — применение закреплённых релизов

Обновляет установленный Config Updates на сервере BB. Закреплённый GitHub-релиз
скачивается в служебный каталог. Локальная ветка разработки и её правки
сохраняются. BB переносит источник плагина с сохранением настроек, секретов и
расписаний. Журнал остаётся в действующей установке.

Если старая версия остановила `fetch` на локальных изменениях, начните с
[перехода со старого Config Updates](../updates.md#переход-со-старого-config-updates).
Обновление уже установленных плагинов подтверждается по фактическим версиям и
источникам. Проверка зависимостей показывает, когда стороннее обновление вышло
за рамки объявленной совместимости.

## Проверка релиза

- Тесты скрипта проверяют загрузку для расходящейся ветки с локальными
  правками, отказ при перемещении тега, перенос плагина и сохранение журнала.
- Тесты зависимости покрывают изменение версии до завершения релиза и после
  его применения. Тесты Config Updates проверяют запуск из исходного проекта
  при расположении самого плагина в каталоге релиза.
