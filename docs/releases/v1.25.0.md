# v1.25.0 — Каскад подписок 0.3.7: свежие квоты после обновления, прерванный ход не уводит тред, Codex через закреплённые ступени

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- **Квоты не устаревают после обновления плагина.** Прежний экземпляр каскада сам снимает свою
  регистрацию и останавливает таймеры; ходы больше не идут через него с устаревшими квотами.
- **«Все ступени исчерпаны» — только когда это правда.** Ступени с неизвестной квотой каскад
  пробует по порядку профиля; закреплённая ступень с неизвестной квотой тоже пробует ход.
- **Прерванный ход не уводит тред на другую машину** и не подписывается «сбоем ступени».
- **Новый тред на закреплённой ступени Codex** открывает сессию по выбранной модели, а не по «Авто».
- После обновления каскад идёт по последней рабочей конфигурации, а не отвечает «профиль не найден».
- `bb subscriptions-cascade limits` отвечает сразу; свежий опрос — `--refresh` (до 10 с).

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `subscriptions-cascade-0-3-7` — Каскад подписок 0.3.7 — отозванный экземпляр не обслуживает ходы, неизвестная квота не даёт отказа, Codex на pin, настройки после переустановки

Исправления по живой работе 0.3.6.
- После переустановки старый экземпляр плагина больше не обслуживает ходы и не держит устаревшие данные о квотах: он сам снимает регистрацию и останавливает таймеры.
- Неизвестная квота больше не даёт отказа «все ступени исчерпаны»: каскад пробует такую ступень, а ждёт сброса и спрашивает владельца, только когда всё действительно исчерпано.
- Прерванный ход больше не уводит тред на другую машину.
- Закреплённая ступень с неизвестной квотой пробует ход. Это касается и Codex на машинах, где квота отвечает HTTP 403; такая ошибка теперь называется своим именем, а не «шлюз».
- Свежий тред на закреплённой ступени Codex открывает сессию на ней, а не падает с кодом 75.
- После переустановки ход идёт по последней сохранённой конфигурации или ждёт настройки, а не отказывает «профиль не найден».
- `bb subscriptions-cascade limits` отвечает сразу; свежий опрос запускается флагом `--refresh`.
Откат: тег agentcli-subscriptions-cascade/v0.3.6.
