# v1.5.0 — Обновление кнопкой, выбор компонентов, README на двух языках

Общий порядок — [docs/updates.md](../updates.md). Состав — [docs/components.md](../components.md).

## Что изменилось

- **«Обновить» без агента.** Config Updates 0.3.0 открывает окно с новыми
  компонентами релиза: название, ссылка на код, описание, галочка (включена).
  Снятая галочка — отказ: компонент не ставится и больше не предлагается. Затем
  плагин сам запускает `updates.py apply` отдельным процессом (он переживает
  перезапуск Config Updates во время обновления) и показывает итог: что
  установлено и обновлено и что сделать самому. «Разобраться с ИИ» — только при
  ошибке или остатке шагов.
- **Выбор при установке из терминала.** `python3 scripts/updates.py apply`
  показывает новые компоненты с описанием и ссылкой: Enter — все, номера — какие
  не ставить. Без вопроса: `--yes` или `--skip id,id`.
- **Проверенные версии внешних плагинов.** В `config/bundle.json` у Handoff,
  Needs You, Tokenomics, KodaForge и ChatGPT Realtime записана версия, с которой
  проверен набор. BB сам плагины не обновляет; если пользователь поставил более
  новую, Config Updates предупреждает, какие наши компоненты могут работать
  неправильно. Ничего не блокируется и не откатывается.
- **README на английском и русском** (`README.md` и `README.ru.md`) в корне, у
  каждого плагина и в отдельных репозиториях (Codex Project Trust, Local
  Transcribe, форк Voice Mode). У Machine Tabs вместо шаблона — настоящее описание.
- `scripts/bundle.py plan` и `choose`; у каждого компонента набора — описание и ссылка.
- Config Updates переезжает на папку каждого нового релиза (`followRelease`),
  поэтому исправления `updates.py` и `bundle.py` доходят до кнопки, даже если код
  самого плагина не менялся.
- Обновление, начатое кнопкой и прерванное, продолжается той же кнопкой
  («Продолжить обновление»); агенту для этого — `apply … --takeover`. Последний
  результат кнопки хранится в `.local/updates/button-run.last.json`.
- Исправлено: новый `bundle.py` принимает набор старого релиза без описаний;
  ошибки набора при `accept` дают отказ, а не трассировку.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `plugin-config-updates-button` — Config Updates 0.3.0: «Обновить» без агента, выбор новых компонентов

Кнопка «Обновить» открывает окно с новыми компонентами релиза: название,
ссылка на код, описание и галочка (по умолчанию включена). Снятая галочка
запоминается (`bundle.py choose --skip`), компонент не ставится и больше не
предлагается. Затем плагин сам запускает `updates.py apply` отдельным процессом
(он переживает перезапуск самого Config Updates) и показывает итог: что
установлено и обновлено, что нужно сделать самому (`attention`). Агент
(«Разобраться с ИИ») предлагается только при ошибке или остатке шагов.
Внешние плагины новее проверенной версии показываются предупреждением.
Нужен путь к bb CLI: по умолчанию `BB_CLI` сервера, иначе — в настройках.

## Проверка релиза

- `python3 -m unittest discover -s scripts -p 'test_*.py'` (выбор компонентов,
  предупреждение о версии, запоминание отказа), `npm test` и `npm run typecheck`
  в `plugins/config-updates` (разбор итога `apply`).
- Изолированный BB 0.50.1 с установленной v1.4.0: переход на кандидат v1.5.0
  командой `apply --skip` — пропущенный компонент не поставлен и записан как
  отказ, Config Updates обновлён до 0.3.0, отключённый плагин остался
  отключённым, повтор без изменений.
- Интерфейс в headless-браузере: кнопка «Обновить до …», окно, фоновый запуск
  «Обновляю…», итог с «Обновлено» и «Сделайте сами»; прерванный запуск
  продолжен тем же владельцем. Сбой стенда (служба сборки BB остановлена)
  дал отчёт с причинами по каждому плагину, повтор довёл установку.
- `updates.py validate v1.5.0` из чистого клона, `privacy_check.py --history`.
