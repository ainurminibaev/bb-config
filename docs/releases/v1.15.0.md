# v1.15.0 — Ещё 13 плагинов — обновления штатно через BB, секреты переносятся

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- **Ещё 13 плагинов bb-config получают обновления штатно от BB**: Project Logo, KodaForge Inspector, Codex Delegation Watch, Context Mode Rollout, Menubar Status, File Local Open, Plugin Keeper, Machine Tabs, PR и Issues, Browser Page, Limit Guard, Project Catalog, Proxy Manager. Шаг переводит их по одному на Git-теги `<id>/vX.Y.Z`; новые версии дальше показывает и ставит сам BB.
- **Секретные настройки переносятся.** BB стирает их при переустановке, поэтому шаг до удаления копирует их во временный файл с правами 600 вне Git и журналов, возвращает после установки, проверяет и удаляет файл. Если секрет прочитать нельзя — остановка до удаления с просьбой спросить владельца.
- Данные плагинов при переходе сохраняются, расписания регистрируются заново (история запусков начинается заново).
- Config Updates остаётся в папке выпуска: ему нужен `scripts/updates.py` рядом.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `plugins-git-source-2` — Ещё 13 плагинов bb-config получают обновления штатно от BB (Git-источник), в том числе с расписаниями, данными и секретами

### Обновления ещё 13 плагинов — штатно через BB

Шаг `plugins-git-source-2` продолжает `plugins-git-source` для плагинов с
расписаниями, своими данными или секретами: Project Logo, KodaForge Inspector,
Codex Delegation Watch, Context Mode Rollout, Menubar Status, File Local Open,
Plugin Keeper (voice-mode-keeper), Machine Tabs, PR и Issues, Browser Page,
Limit Guard, Project Catalog, Proxy Manager. После него их новые версии
показывает и ставит сам BB (Settings → Updates, `bb plugin update`).

Как и раньше, по одному: сборка по тегу до удаления, сохранение и возврат
настроек, проверка `running`. Что проверено на изолированном BB и на установке
автора: данные плагинов (хранилище и файлы) при переустановке сохраняются;
расписания регистрируются заново и работают (история запусков начинается
заново); секретные настройки BB при удалении стирает — поэтому шаг до
удаления копирует их во временный файл с правами 600 вне Git и журналов,
возвращает после установки, проверяет, что BB видит их заданными, и удаляет
файл. У Proxy Manager после шага прокси, привязки и маршруты те же, проверка
соединения проходит. Если секрет прочитать нельзя, шаг останавливается до
удаления и просит спросить владельца установки.

Config Updates остаётся в папке выпуска: ему нужен `scripts/updates.py`
рядом, а установка из Git этого не даёт.

## Проверка релиза

Из чистого клона коммита выпуска: `python3 scripts/updates.py validate v1.15.0`, `python3 -m unittest discover -s scripts -p 'test_*.py'` (в том числе 15 тестов `test_plugin_git_source.py`: перенос секретов, откат с секретами, остановка при нечитаемом секрете), `python3 scripts/privacy_check.py --history`. На изолированном BB: данные и расписания Limit Guard и Proxy Manager после перехода, полный цикл секретов Proxy Manager с проверкой соединения через тестовый прокси. На установке автора все 13 плагинов переведены: `running`, настройки и контрольные суммы файлов данных совпали, расписания зарегистрированы; у Proxy Manager прокси, привязки и маршруты те же, проверка соединения через оба прокси проходит, файл с секретом удалён.
