# v1.21.0 — Каскад подписок: треды сами переходят между подписками при лимите

Общий порядок — [docs/updates.md](../updates.md).

## Что изменилось

- Новый экспериментальный плагин **Каскад подписок** (`agentcli-subscriptions-cascade`) —
  свой провайдер BB с профилями «Авто», «Авто · без Codex», «Opus → Авто» и другими.
  Тред на каскаде сам переходит между подписками на разных машинах, когда у текущей
  кончается лимит. Порядок ступеней задаётся в настройках. Переход на Codex — после
  подтверждения карточкой. После сброса лимита тред возвращается на приоритетную ступень.
- Аккаунт не покидает свою машину: каждая ступень работает своим нативным CLI на своей
  машине. Файлы треда синхронизирует Mutagen через общий путь `/opt/bbfs`. Сессия
  продолжается с памятью (`--resume`), переход Claude ↔ Codex передаёт сводку и исходную
  просьбу. Опоздавшие записи и конфликты уходят в `~/bbfs-quarantine` со строкой в ленте.
- Каждая смена ступени видна строкой в ленте треда. Мастер «Настроить» один раз готовит
  машину: Mutagen, общий путь, SSH-ключ до опоры с согласием. `bb subscriptions-cascade gc`
  убирает копии архивных тредов.
- Плагин не ставится автоматически: в наборе он **необязательный** (`"optional": true`,
  новое поле `config/bundle.json`). Поставить: `python3 scripts/bundle.py choose --take
  agentcli-subscriptions-cascade` в checkout bb-config на сервере BB, затем обновление
  доработок. Без него остальные плагины работают как раньше.
- Совместимость с каскадом: Limit Guard 0.10.0, Thread Account Usage 0.3.1 (шапка треда по
  текущей ступени, остаток VClaude), Codex Delegation Watch 0.3.0, File Local Open 0.4.0,
  Project Open 0.4.0, Git Thread Provenance 0.2.0. Тред каскада узнают по паспорту
  (`threadStatus`), остальные треды не меняются.
- Также вошли накопленные обновления: Thread Account Usage 0.2.2–0.2.3 (Antigravity, машина
  VClaude), Plugin Keeper 0.2.13, Machine Tabs 0.2.19, Menubar Status 0.3.10,
  Proxy Manager 0.3.6, Thread Description 0.1.1.

## Шаги

### `bundle` — Полный набор компонентов bb-config

Выполняется первым. Сводит установку к заявленному набору `config/bundle.json` этого релиза: ставит отсутствующие компоненты, обновляет устаревшие (собственные плагины — из закреплённого коммита, форки и каталоговые — штатным `bb plugin install`/`update`), проверяет и чинит их настройку (например, мост Voice Mode). Исключённые пользователем компоненты не ставятся, отключённые остаются отключёнными, плагины из другого источника не заменяются. Личные входы, настройки и действия на других машинах перечисляются в отчёте (`attention`). Затем шаги пропущенных релизов проверяются по уже сведённому состоянию.

### `account-usage-antigravity` — Thread Account Usage 0.2.2 — Antigravity (Google и Antig), единая шкала лимитов, страница «Аккаунты и объёмы»

«Все аккаунты» показывает два провайдера Antigravity CLI: Google Antigravity
(квоты по группам Gemini и Claude+GPT, тем же API, что опрашивает сам `agy`)
и Antig (пакет часов из кабинета antig.ru; к шлюзу gate.antig.ru плагин не
обращается). Все лимиты — на одной шкале: полоса — израсходовано, засечка —
сколько прошло окна или срока пакета, красная засечка — расход опережает время.
Подписки и пакеты — отдельными разделами, вкладка «Пакеты».

Новая страница «Аккаунты и объёмы» в боковом меню: обзор с фильтрами, объём
тарифов в токенах с источником (замер / оценка / официально), история
израсходованного (раз в 15 минут), «Обсудить объёмы» — тред BB со сводкой.
Экран VClaude стал её вкладкой. У Antig в выборе провайдера свой значок.

Для лимитов Antig нужна сессия кабинета antig.ru в `~/.local/state/bb-antig/session.json`
(0600, вне репозитория); без неё запись показывает «лимиты недоступны».
Откат: тег thread-account-usage/v0.1.3.

### `account-usage-vclaude-machine` — Thread Account Usage 0.2.3 — строка VClaude: машина Claude Code и срок очереди пакетов

В «Все аккаунты» → «Пакеты» под подписью VClaude видна машина, где Claude Code
настроен расходовать этот пакет, — так же, как Tru под «Прямой Gemini». Машину
определяет сам плагин: на каждой машине он читает из `settings.json` Claude Code
только хост `ANTHROPIC_BASE_URL` (токены не передаются) и показывает те машины,
где это `vclaude.ru`, под их текущим именем в BB. Квоту по-прежнему читает
сервер BB; квота, срок, процент и переход в подробности не изменились.
Машина со старой сборкой плагина в строку не попадает до обновления.

Очередь пакетов VClaude: докупленный пакет ждёт, пока у текущего не кончится
лимит или срок, и его 30 дней идут с этого момента. Раньше строка брала срок
текущего пакета (например, 3-дневного промокода) и считала его 30-дневным:
дата «до …» была ранней, а засечка времени и предупреждение «пакет может
сгореть» — ложными. Теперь срок — конец всей очереди («не позже»), засечка —
от начала текущего пакета, в подсказке и на вкладке VClaude видно, какой пакет
идёт и какой следующий. Ждущий пакет учитывается в «Оплачено».
Откат: тег thread-account-usage/v0.2.2.

### `codex-watch-cascade` — Codex Delegation Watch 0.3.0 — надзор за тредом каскада на ступени Codex

Дочерний тред «Каскада подписок», чья текущая ступень — Codex, ставится под надзор как тред Codex. Если каскад увёл тред на другую ступень, надзор не подталкивает его подсказками про /goal, а resume-goal отказывает с пояснением. Треды Codex и Claude Code — как раньше.
Откат: тег codex-delegation-watch/v0.2.0.

### `file-local-open-cascade` — File Local Open 0.4.0 — файлы треда каскада с машины свежей копии

Откат: тег file-local-open/v0.3.0.

### `keeper-usage-antigravity` — Plugin Keeper 0.2.13 — строки Antigravity и VClaude в Usage

### `limit-guard-cascade` — Limit Guard 0.10.0 — тред «Каскада подписок»: лимиты текущей ступени, без «финиша»

Для треда «Каскада подписок» (providerId subscriptions-cascade) Limit Guard читает паспорт треда (RPC каскада threadStatus) и считает лимиты текущей ступени: её машины и провайдера. «Финиш» для такого треда смягчается до экономного режима: каскад сам переходит на следующую подписку между ходами. Ступень через шлюз квоты подписки не имеет — режим не выставляется. Тред каскада получает инструмент limit_status. Каскад не установлен или не ответил — поведение прежнее; треды Claude Code и Codex не меняются.
Откат: тег limit-guard/v0.9.2.

### `machine-tabs-project-roles` — Machine Tabs 0.2.19 — роли на первой странице проекта

на раскрытого родителя — на месте счётчика появляется стрелка. Повторная

### `menubar-status-antigravity` — Menubar Status 0.3.10 — строки Google Antigravity и Antig в меню

«5ч» — самая загруженная из 5-часовых групп (Gemini или Claude+GPT), остальные
передаются под своими именами. Antig показывается как пакет, как VClaude.
Серверная часть работает сразу; новые клиенты Mac (Swift, panel.html) и Windows

Откат: тег menubar-status/v0.3.9.

Эта папка добавляется в список, который знает обработчик Finder. Режимы «Файлы» и рабочее окно BB, а также пункт в меню «…» остаются штатными. Каскад не установлен или не ответил — как раньше.

### `subscriptions-cascade-scaffold` — Каскад подписок (экспериментальный): свой провайдер, ход по ступеням машин, синхронизация Mutagen

Появился экспериментальный плагин «Каскад подписок» (`agentcli-subscriptions-cascade`).
Свой провайдер BB: ход идёт на первой ступени «машина × CLI × аккаунт», у
которой есть лимит, CLI запускается на машине ступени, файлы проекта
синхронизирует Mutagen по общему пути. Экран настроек: машины (с «SSH к
опоре»), порядок ступеней, профили каскада со схемой «i», тестовый источник
квоты, таблица моделей, файлы и мастер «Настроить». Переход Claude ↔ Codex
внутри треда и карточка подтверждения в ходе — ещё в разработке.

Автоматически плагин не ставится и в набор (`config/bundle.json`) не входит.
Поставить вручную на сервере BB: `npm ci --prefix plugins/agentcli-subscriptions-cascade`,
`bb plugin build plugins/agentcli-subscriptions-cascade`,
`bb plugin install ./plugins/agentcli-subscriptions-cascade --yes`.
Проверка: Настройки → Плагины → «Каскад подписок» открывает экран каскада;
в выборе провайдера появляется «Каскад подписок» с профилями «Авто»,
«Авто · без Codex», «Opus → Авто», «Fable → Авто», «Только Opus 5.5», «Только Fable 5.2». Запишите результат через `record` с тем, что увидели, или отказ.

### `thread-account-usage-cascade-vclaude` — Thread Account Usage 0.3.1 — шапка треда каскада по текущей ступени и остаток пакета VClaude

Две доработки шапки треда в одной версии (0.3.0 совместимости с каскадом и
0.2.4 шапки VClaude сведены в 0.3.1).

**Тред «Каскада подписок».** Кольцо в шапке показывает квоту текущей ступени:
провайдера, машину и аккаунт из паспорта каскада; в подписи — «ступень
каскада». Каскад не установлен или не ответил за 3 с — как раньше.

**Тред Claude Code через VClaude.** Тред на машине, где Claude Code настроен на
шлюз VClaude (`ANTHROPIC_BASE_URL` на `vclaude.ru`), раньше показывал
«не подтверждён» и «Лимиты не подтверждены». Теперь шапка показывает «VClaude»
и остаток пакета вместо колец, например «380,73 млн из 405 млн · до 27 дек», с
цветом по остатку (10 % и меньше — предупреждение). Клик открывает «Аккаунты и
объёмы» на вкладке VClaude. Кабинет недоступен — «VClaude · остаток неизвестен».
Машину плагин определяет по хосту `ANTHROPIC_BASE_URL` через метод машины из
0.2.3 (токены не передаются); машина со сборкой старше 0.2.3 шапку не меняет.

**Тред каскада на VClaude.** Главный признак — ступень каскада `kind: gateway`
VClaude: шапка та же, остаток пакета. Запасной путь — ступень-подписка Claude
Code на машине, чей Claude Code направлен на VClaude.

Остальные треды не меняются. Откат: тег thread-account-usage/v0.2.3.

### `thread-description-hover` — Thread Description 0.1.1: карточка открывается сразу при наведении

Обновляет плагин Thread Description до 0.1.1: карточки «i» и сводки
открываются сразу при наведении мыши (раньше — с задержкой и не во всех
окнах приложения), системная подсказка поверх карточки больше не всплывает.

Проверка: навести мышь на «i» у названия треда — карточка появляется сразу.
