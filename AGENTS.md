# Личные доработки BB

Этот репозиторий — источник восстановления личной конфигурации BB. Сохраняй здесь
каждую установку, удаление, включение, отключение и доработку плагина, а также
изменение настроек BB. Это относится и к сторонним плагинам: Needs You имеет ID
`inbox`, Handoff — `handoff`, отдельная кнопка к нему — `handoff-button`.
Сторонние плагины сохраняй установленными из каталога, чтобы получать обновления.
Для дополнительных кнопок предпочитай маленький отдельный плагин, который
открывает существующий экран оригинала. Не дублируй его формы своим попапом.
Не создавай форк ради UI-кнопки без отдельного согласования.

После изменения работающего BB:

1. Проверь установленный путь и источник через `bb plugin list --json`.
2. Обнови приватный снимок `.local/config/`: `python3 scripts/snapshot.py --settings-only`.
3. Для своей доработки сохрани исходники в `plugins/<id>/`. Установленную версию
   на сервере и checkout на другой машине нельзя считать автоматически синхронизированными.
4. Обнови `docs/customizations.md`: что изменено, зачем, где работает и как
   восстановить. Если добавлен новый вид настройки, дополни restore.py или явно
   опиши ручной шаг. Не оставляй сохранённый JSON без способа применения.
5. Проверь `python3 scripts/snapshot.py --check` и diff. Не объявляй сохранение
   завершённым, если изменение осталось только в работающем BB. Коммит и push
   делай в рамках поручения пользователя; незакоммиченные изменения не скрывай.

Любую кастомизацию BB заноси в этот репозиторий в рамках той же задачи:
установку, обновление, удаление или переключение стороннего плагина, собственную
доработку, изменение настроек, навыков или инструкций. Для стороннего плагина
сохраняй источник из каталога, версию и состояние, настройки — в приватном снимке;
не копируй его исходники и не создавай форк без необходимости. Для каждой
кастомизации актуализируй документацию и способ восстановления.
Это включает установку готового плагина с настройками поверх или рядом:
дополнительные кнопки, плагины-спутники, совместимость, интеграции, привязки
и сопутствующие настройки сохраняй как единое восстанавливаемое изменение.

Новый собственный плагин обязательно добавляй в `plugins/<id>/` вместе с
исходниками, манифестом, lock-файлом зависимостей и навыком использования.
Добавляй обезличенную запись установки в `config/plugins.json`, чтобы плагин
восстанавливался из репозитория. Одновременно обновляй `docs/customizations.md`:
поведение, ограничения, команды установки/обновления, проверки и восстановления.
При изменении существующего плагина актуализируй его навык и документацию;
нельзя считать работу завершённой, если новая версия есть только в работающем BB.

`scripts/restore.py` показывает план, `--plugins --apply` устанавливает плагины
и применяет поддерживаемые настройки. Порядок восстановления и ограничения —
в `docs/customizations.md`. `scripts/setup_tracking.py --apply` включает
напоминание для всех проектов BB и Git-хук проверки снимка.

Не коммить секреты, авторизации, базы, переписки и вложения. Снимок исключает
секретные поля схемы, но свободный текст и исходники тоже проверяй перед коммитом.
Не читай и не меняй базу BB напрямую: используй штатные API/SDK/CLI.
Изменения маршрута Claude и тесты с изменением его IP требуют отдельного явного
поручения. Сохранение настроек не является таким поручением.

`scripts/snapshot.py` без `--settings-only` копирует установленную версию плагинов.
Не запускай его поверх незакоммиченных исходников. Текущий путь установки всегда перепроверяй через CLI. Изменение локального файла ещё не обновляет плагин на другой машине.

Эти инструкции общие: BB читает `.bb/AGENTS.md` (ссылку на этот файл), Codex CLI —
корневой `AGENTS.md`, Claude Code — импорт из `CLAUDE.md`. Меняй правила здесь.

## Публичный код и личная конфигурация

`config/` содержит только обезличенные настройки и примеры. Снимок действующей
установки записывается исключительно в игнорируемую `.local/config/`.
`restore.py` объединяет словари по верхнему уровню; локальные значения имеют
приоритет, списки заменяются целиком. Вложенные объекты переопределяй целиком.
Не переноси адреса серверов, машин, прокси, идентификаторы и личные инструкции
в публичные файлы. Личные инструкции и старые документы хранятся в `.local/docs/`.
Секреты и авторизации в снимок не включаются даже локально.
Перед коммитом: `python3 scripts/privacy_check.py --staged`.
Перед публикацией: `python3 scripts/privacy_check.py --history`.
Личную часть сохраняй зашифрованно через `scripts/private_backup.py`;
GitHub её не восстанавливает. Снимок конфигурации не заменяет бэкап BB.

## Базовые настройки CLI при установке новой машины

При установке или обновлении Codex, подключении новой машины либо восстановлении
окружения выполни на целевой машине под пользователем запуска CLI:
`python3 scripts/codex_defaults.py --apply --verify` из checkout bb-config.
Проверь `--check --verify`. Defaults хранятся в `config/codex.json`; не копируй
полный профиль Codex с авторизациями. При отдельном CODEX_HOME повтори для него.
`restore.py --apply` применяет defaults на текущей машине автоматически.

После применения к существующей машине для старых BB-тредов достаточно
освободить runtime штатной командой bb thread stop, сохранив историю.
Работающие ходы сначала должны завершиться; историю не очищай.

## Обновления для установивших доработки

Полный порядок — `docs/updates.md`; он обязателен. Кратко:

- Пользователи узнают об изменениях только через опубликованный стабильный
  GitHub Release `vX.Y.Z`. Commit и push сохраняют разработку и сигналом не
  являются. Релиз создаётся только по отдельному поручению «публикуй
  обновление», на проверенном коммите; опубликованный тег не перемещается.
- Изменение, которое должно дойти до пользователей (плагин, настройка, скрипт,
  ручное действие), в той же задаче получает ожидающий шаг — отдельную пару
  файлов `docs/releases/next/<id>.json` и `<id>.md`: стабильный ID,
  зависимости, проверка фактического состояния, скрипт применения, ожидаемый
  результат, повтор и восстановление. Изменённый плагин получает новую версию
  в `package.json`. Шаг коммить вместе с его изменением. Файлы выпущенных
  версий `docs/releases/vX.Y.Z.*` собирает только `python3 scripts/updates.py
  release` при публикации; чужие шаги и версии не дописывай. В релиз входят
  только шаги с закоммиченным содержимым; проверка — `validate` из чистого
  клона коммита.
- Повторяемые действия оформляй проверяемыми скриптами (`--check`/`--apply`),
  а не текстом для ручного исполнения. Не подставляй в них пути, ID машин,
  адреса и настройки автора.
- Применено у автора при разработке и опубликовано — разные состояния. Шаг у
  автора проверяется `python3 scripts/updates.py run next/<id> --development`.
  После публикации установка автора проходит обычное обновление: применённое
  проверяется, а не накатывается повторно.
- Применяя обновление у пользователя, работай только с закреплёнными тегом и
  коммитом через `scripts/updates.py` (`fetch`, `begin`, `run`/`record`,
  `finish`). Не исполняй `main` как стабильную версию, не делай принудительный
  сброс checkout, не применяй `scripts/restore.py` и снимок автора на чужой
  установке, сохраняй личные настройки и выбранные компоненты.
- Шаг считается выполненным только после проверки результата на конкретной
  машине; сервер BB и машины-исполнители учитываются раздельно. Тег, checkout
  или запись режима `development` установкой не считаются. Частичный результат
  не объявляй завершённым; при прерывании продолжай остаток. Параллельный
  запуск обновления запрещён: отказ `begin` означает, что работает другой тред.
- Ошибка проверки релизов (сеть, лимит GitHub) — это ошибка, а не «обновлений
  нет».
- В этом checkout одновременно работают несколько тредов. Перед коммитом
  сверяй каждый файл с HEAD и добавляй только свои фрагменты; общий файл
  целиком не добавляй.
- Механизм: плагин `plugins/config-updates/` (проверка, карточка в боковой панели, кнопка
  «Обновить с ИИ», `bb config-updates`), скрипт `scripts/updates.py`, журнал
  `.local/updates/` (в Git не попадает). При их изменении обновляй навык
  плагина, `docs/updates.md` и тесты.

## Продукты, устанавливаемые отдельно

У каждого плагина один дом в config/plugin-homes.json (формат —
docs/customizations.md): bb-config, project или ignore. Плагины с домом
project/ignore (и старый список config/externally-managed-plugins.json) не
входят в комплект bb-config. Не добавляй их в manifest, снимки настроек,
plugins/ или патчи этого репозитория. Snapshot/restore учитывают исключение;
restore ставит project-плагины командой из их проекта.
Перед снимком проверь дом: `python3 scripts/plugin_scope.py show <id>`. Если
дома нет — один раз спроси пользователя (bb-config, проект: какой, откуда и
какой командой ставится, или не отслеживать) и запиши ответ
`plugin_scope.py set`; личные проекты — с `--private`. Больше не спрашивай. Их исходники,
инструкции и восстановление относятся к соответствующему продукту.
Личный помощник, его сервисы и Telegram-зависимость устанавливаются отдельно;
копии памяти, проектных MCP и навыков помощника здесь не хранить.
