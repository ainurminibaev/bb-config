# Генерация изображений в BB

## Кто как генерирует

- **Codex** со встроенным `image_gen`: генерирует сам (системный навык imagegen, встроенный
  инструмент, не CLI/API). Выбранный файл копирует из `$CODEX_HOME/generated_images/…` в папку
  проекта с новым именем, не перезаписывая существующие файлы.
- **Codex без рабочего image_gen** (инструмента нет в сессии, лимит, ошибка доступа): один раз
  вызывает `image_generate` с `reason=codex_unavailable` или `codex_limited`;
  при лимите — `excludeCurrentAccount=true`. Встроенный вызов в цикле не повторяет.
- **Claude, Pi, Cursor и другие**: вызывают `image_generate`
  (CLI-эквивалент: `bb image-gen generate --prompt … --out <dir> [--ref <file>]`).

## Вызов image_generate

- `outputDir` — абсолютная папка на машине текущего треда (обычно внутри проекта).
- `references` — абсолютные пути к референсам на этой же машине; их копирует сам сервис.
- `count` — сколько вариантов нужно пользователю. Вариантов «про запас» не делай.
- Ответ с `state=completed` уже содержит пути файлов — покажи их пользователю.
- Ответ с `jobId` и `wait` означает: заверши ход. Результат придёт **одним** уведомлением
  в этот тред. Не опрашивай статус в цикле и не вызывай генерацию повторно.

## Ошибки

- `limited` — лимит подписки Codex. Сообщи пользователю (с `resetHint`, если он есть);
  не повторяй сам.
- `unknown` — связь с исполнителем потеряна после старта, картинка могла быть сгенерирована.
  Повтор возможен только после явного согласия пользователя: `image_retry` с `confirmUnknown=true`.
- `return_failed` — картинка есть, не доставлен файл: `image_retry` повторяет только доставку.
- `failed` без исполнителя — покажи `image_services`: на какой машине чего не хватает.

Рядом с каждой картинкой лежит описание происхождения: задание, исполнитель, хеш запроса,
референсы и SHA-256.
