# Thread Account Usage

Показывает лимиты подписки отдельно от расхода токенов треда.

В заголовке: два вложенных кольца, штатный логотип по центру кольца; рядом
колонка с аккаунтом сверху и машиной снизу. Каждое окно лимита образует
отдельную колонку: подпись и процент сверху, время до сброса с `↻` снизу.
Точная дата и пояснение процента доступны по наведению.
Порядок фиксирован: сначала 5ч, затем неделя; процент расхода не меняет
порядок колонок и колец. Применимые к модели и прочие окна следуют
за общими; показываются первые два полученных окна. Если провайдер
сообщает одно окно, кольцо одно. Рядом остаётся график Tokenomics с подписью
«Тред / 24ч» на широких экранах. Внизу сайдбара: два кольца и выровненные средние расходы 5ч и
недели; недельная строка приглушена. Счётчик доступных сбросов `+N` занимает отдельное место справа от кольца. Тексты увеличены,
проценты выровнены. Единицы времени разделены узким
неразрывным пробелом. Красная точка у нижнего значка означает только
подтверждённое исчерпание общего окна 5ч/недели; число таких аккаунтов видно
в заголовке карточки. Модельные ограничения и устаревшие данные не считаются
недоступностью всего аккаунта.
Средний процент не означает доступность каждого аккаунта. При обновлении
данные не очищаются; SVG-стрелка вращается вокруг центра viewBox в кнопке
постоянного размера. Карточка
закрепляется при взаимодействии. Её React-состояние отделено от меняющихся
DOM-якорей, чтобы перестройка заголовка не закрывала её.

Наведение открывает карточку, нажатие закрепляет её. Escape, крестик и нажатие
вне карточки закрывают её. Общий обзор показывает строки аккаунтов и короткие
горизонтальные полосы 5ч / неделя / модель, подписи и время справа от полос.
Названия машин перечислены; длинные имена доступны в подробностях. Точная
дата — по наведению или в подробностях. Кнопка `›` открывает полные данные
и до шести последних тредов этого агента на этих машинах. Историческая
привязка тредов к этому аккаунту не утверждается. Переключатели выделяют
нужное окно без смешивания разных окон.
Отсутствующее окно отображается прочерком, а не нулём или подстановкой недели.
Даты форматируются в часовом поясе клиента.

На телефоне (до 767px) отдельного баннера над вводом нет: короткая кнопка
с логотипом, кольцами и главным процентом встроена в существующую нижнюю
горизонтально прокручиваемую строку метаданных треда. Нажатие открывает
карточку с аккаунтом, машиной, всеми окнами и временем сброса снизу экрана.
Внизу сайдбара подписи 5ч и недели сохраняют две выровненные строки.
Десктопное размещение не меняется. На мобильном экране pointerdown/mousedown по кнопкам нижней строки сохраняет фокус редактора до click, чтобы blur не сворачивал панель раньше открытия меню. Обработчик не останавливает распространение событий и не перехватывает touchmove; десктоп не затрагивается. Используются visualViewport для клавиатуры и safe-area для
системного жеста; заголовок и переключатели остаются доступны при прокрутке.
На узких экранах до 350px строки адаптируются без горизонтального скролла.

`+N` показывает известные доступные сбросы. Для Codex read-only host worker
использует установленный `codex app-server --stdio`: только initialize,
account/read (refreshToken=false), account/rateLimits/read. Количество
привязывается только при совпадении email с usage и не суммируется для одного
логина на нескольких машинах. Сбросы Claude пока обозначаются «не сообщены»:
неизвестное значение не превращается в 0. Потребление сбросов не реализовано.

## Данные и ограничения

Данные приходят через SDK BB: машина определяется по environment треда,
модель — по метаданным последнего запуска. Запрашивается только usage этой
машины. Идентичность аккаунта — текущий вход CLI на машине, а не доказанная
идентичность уже запущенного процесса. Метаданные запуска проверяются на
нестандартные профили и маршруты авторизации; при их наличии, отсутствии
метаданных или включённом пуле аккаунт треда обозначается неподтверждённым.
Аккаунт из другой машины никогда не подставляется. Смена модели ещё до запуска
следующего сообщения не меняет модель последнего запуска в карточке.

Периодический запрос выполняется каждые 2 минуты, при фокусе окна и вручную.
Запросы одной машины объединяются, результаты кешируются на 2 минуты в памяти.
На ошибке последние известные данные явно отмечаются устаревшими. Таймер
обратного отсчёта обновляется каждые 30 секунд. Если срок уже наступил, UI
предлагает обновить данные, не обнуляя расход самостоятельно.

Один логин на нескольких машинах объединяется по email и провайдеру,
проценты не суммируются. Переписки, базы, токены авторизации и файлы CLI не
читаются. Данные об аккаунтах не сохраняются на диск плагином.

## Установка и восстановление

На сервере BB:

```sh
cd plugins/thread-account-usage
npm ci --no-audit --no-fund
bb plugin build .
bb plugin install . --yes
```

Для обновления: сборка и `bb plugin reload thread-account-usage`.
Проверки: `npx tsc --noEmit --skipLibCheck` и `node --test logic.test.ts`.

Прямое добавление UI через `experimental_appOverlay` использует узкие DOM
якоря BB 0.49: `[data-thread-header-workflow-actions]`, `[data-split-pane-id]`
и штатное нижнее меню. Раскладка split берётся из SDK `useSidebarSplitLayout`.
Если якоря изменились, плагин не переносит UI в случайные места.

Единственная настройка `hideGlobalTokenomics` (по умолчанию true) скрывает
только `[data-bb-plugin="tokenomics"][data-top-bar-slot="tokenomics"]` стилем
нашего плагина. Установленные файлы Tokenomics не меняются. Настройку можно
выключить через BB. Отключение нашего плагина удаляет созданные DOM-якоря и
стили и возвращает верхний левый индикатор.

Usage Tracker остаётся установленным из каталога, но отключён во избежание
двух нижних индикаторов. Возврат: отключить `thread-account-usage`, включить
`usage-tracker`. Управление профилями, маршрутизацией и сбросами лимитов этот
плагин не выполняет.

Тариф аккаунта показывается с ценой в месяц из статичной таблицы (`planLabel` в `logic.ts`: Claude Pro $20, Max 5x $100, Max 20x $200; ChatGPT Plus $20, Pro $200, Free $0): отдельной строкой под машинами в списке «Все аккаунты», а также в шапке подробностей и в строке аккаунта треда. При смене прайса таблицу нужно поправить.
