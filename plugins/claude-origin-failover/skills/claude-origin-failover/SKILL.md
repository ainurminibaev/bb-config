---
name: claude-origin-failover
description: Проверка подключения отдельного плагина к штатному Claude Code в одном тестовом треде BB на Tru.
---

Для проверки укажи существующий изолированный Claude-тред на Tru через
`bb plugin config claude-origin-failover set testThread <thread-id>`.
В следующем ходе этого треда вызови `printenv BB_ORIGIN_PROBE`.
Значение `origin-shim-v1` подтверждает запуск обёртки штатным мостом.
Проверяй запись результата инструмента в журнале треда.
Заверши проверку через `bb plugin config claude-origin-failover unset testThread`.

Для изолированной текстовой проверки на другом хосте плагин поддерживает
`testRemoteHost` (ID машины). Нужна предварительно подготовленная нативная
история синтетической сессии в проекте `/tmp/bb-origin-relay/<thread-id>`
на этом хосте. Пересылать файлы авторизации или домашний каталог запрещено.
При отсутствии истории relay завершает запуск с ошибкой. В этой сборке на
удалённом ходе выключены инструменты. Перед обратным ходом требуется перенести
новые сообщения в изолированную нативную историю исходной машины. Использовать
этот режим для рабочих разговоров преждевременно.
После опыта очистить обе настройки. Их пустые значения оставляют штатный
Claude провайдеру BB.

Одноразовый сквозной эксперимент запускают только в выделенном синтетическом
треде. Задай testThread, testRemoteHost и уникальный quotaProbe
(буквы, цифры, дефис, подчёркивание). При первом ходе локальная HTTP-фикстура
отдаёт Claude CLI ошибку 429. Штатный provider-retry ставит один повтор.
Запускатель проверяет метку эксперимента при фактическом старте процесса.
Claude на резерве получает видимые текстовые сообщения из журнала BB.
После успешного ответа резервного Claude следующий ход обрабатывает исходная
машина. Для проверки попроси резерв придумать новое слово, затем попроси
повторить его на исходной машине. Проверь provider-retry explain, события
треда и журнал claude-origin-relay.log. По окончании очисти quotaProbe,
testRemoteHost и testThread. Для повторения используй новый ID опыта.

Для рабочего режима в Claude-треде на основной машине нажми «Автопереход»
рядом с Handoff в поле ввода и включи «Автопереход в этом чате». pilotOrigin и
pilotBackup — идентификаторы основной и резервной машин. Выбор сохраняется
для одного треда. При настоящем отказе по квоте с известным временем сброса
штатный provider-retry повторяет ход. Дальнейшие ходы остаются на резерве
до сброса. При двух известных исчерпанных окнах запланирован повтор около
первого сброса. Отключение в панели возвращает разговор на основную машину.
Для восстановления выполни npm ci --ignore-scripts и bb plugin build .
в каталоге плагина, затем bb plugin reload claude-origin-failover.
Проверь наличие app.bundle. Восстанови также route.css и все файлы bin/.

На резерве workspace предлагает git_status, read_file и edit_file для
исходного окружения BB. edit_file принимает SHA-256 предыдущего чтения.
Резерв получает видимые текстовые сообщения и поддерживаемые вложения
(до 1 МиБ каждое; история читается страницами и передаётся без отсечения старых сообщений).
Для команд BB используй workspace.bb_cli с argv без начального bb. Например, ["status","--json"]. Установленный CLI запускается в терминале исходного треда с его проектом и окружением. Для долгих команд используй возвращённый terminalId и штатные terminal output/send. Для старого изолированного опыта origin-tools-<ID> на
Tru нужен /tmp/origin-tools-<ID> с tests/origin-fixture.py под именем fixture.py
и синтетическим marker.

Для одного согласованного живого прогона используй отдельный testThread, testRemoteHost и уникальный quotaProbe с префиксом live-once-. В этом режиме локальный Claude обращается к своему провайдеру. Нативный отказ по окну подписки оставляет метку только на исходной машине. Следующий штатный повтор может передать на резерв ровно одно сообщение пользователя. Для каждого опыта используй новый ID. По окончании проверь журнал, очередь, очисти три тестовые настройки.
