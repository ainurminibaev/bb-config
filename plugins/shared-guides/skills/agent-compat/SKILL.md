# Совместимость агентов

Образец: `marusya-os/AGENTS.md`, раздел «Совместимость агентов» (проект marusya).

## Правила проекта
- Всё содержание — в AGENTS.md. Рядом CLAUDE.md из одной строки `@AGENTS.md`;
  вложенные каталоги — та же пара.
- Содержательный CLAUDE.md не создавай (в Claude Code это отклоняет хук
  claude_md_guard из bb-config). Нашёл старый — предложи перенести в AGENTS.md;
  без согласия не переноси.

## Навыки
- Формат SKILL.md (Agent Skills): frontmatter `name` и `description` с условием
  применения, словами пользователя.
- Одна настоящая папка и относительная ссылка на неё, чтобы навык видели оба:
  `.agents/skills/<имя>` (Codex) и `.claude/skills/<имя>` -> `../../.agents/skills/<имя>`
  (Claude). Проверь, что ссылка попала в Git.
- Общие навыки BB для всех проектов доставляет плагин (`skills/<имя>/SKILL.md`).

## Формулировки без привязки к агенту
- Пиши «навык X», «команда bb …», а не «вызови /команду», «MCP X», «инструмент Task».
- Перед использованием проверь, что инструмент реально есть в этой сессии; нет —
  возьми CLI-эквивалент или сообщи об ограничении.

## Хуки и MCP
- У каждого агента свои: Claude — `.claude/settings.json`, `.mcp.json`;
  Codex — `.codex/hooks.json`, `config.toml`. Сверь формат с установленной версией.
- Важный хук подключай в оба, логику держи в одном общем скрипте; проверь
  срабатывание в каждом агенте.
- MCP добавляй обоим или запиши, почему только одному. В Claude — scope
  project или user, не local.
