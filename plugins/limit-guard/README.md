# Limit Guard

Задача: работа не теряется, когда лимит подписки кончается посреди хода, и
её может подхватить другой агент, модель или машина. Главное правило:
**сохраняет код плагина, а не модель.** Когда лимит обрывает ход, модель уже
ничего сделать не успеет.

## Что делает

- **Снимок незаконченной работы.** Это коммит всего состояния папки треда под
  служебной ссылкой `refs/wip/bb/<окружение>`, собранный через временный
  индекс. Рабочие файлы, текущая ветка и индекс не меняются, в списке веток
  ничего не появляется.
  - В снимок попадают изменённые и новые файлы. Не попадают игнорируемые,
    файлы крупнее 20 МБ и каталоги вроде `node_modules`.
  - Следующий снимок наследует прошлый, поэтому force-push не нужен. Если
    папка совпала с веткой, локальный снимок убирается.
  - Для папки без git снимок пишется в теневой репозиторий в данных плагина
    на той же машине, `.git` в папке не появляется.
  - Когда снимок делается: ход прервался по любой причине; тред вошёл в
    режим финиша; тред затих с правками (не чаще раза в 10 минут на папку);
    тред с worktree ушёл в архив (до удаления копии).
  - На сервер снимок уходит, только если GitHub подтвердил, что репозиторий
    приватный (`gh api`), и в изменённых файлах нет похожего на секреты.
    Иначе он остаётся на машине.
- **Сообщение в идущий ход.** Раз в 2 минуты сервер смотрит лимит у
  работающих тредов Claude Code и Codex. Если режим ухудшился, в ход
  отправляется одно короткое сообщение `[limit-guard] …`. Пороги
  настраиваются:

  | Окно | Экономный | Финиш |
  |---|---|---|
  | 5 часов | 75% или до упора меньше 40 мин | 90% или до упора меньше 10 мин |
  | Неделя и окно модели | 90% | 97% |

  «До упора» считается по темпу роста окна за последние полчаса. Окно
  модели учитывается, только если тред работает на этой модели. При скором
  сбросе совет — «сохранись и жди», при полном окне модели — сменить модель.
- **Правила для агента.** Ради лимита не коммитить. Коммиты — только
  законченные шаги и только свои файлы по именам, push — по правилам проекта.
  В общей папке не переключать ветку и не делать stash, reset, pull, rebase.
- **Тред упёрся в лимит.** Плагин ждёт до минуты решения `provider-retry`.
  Push-уведомление приходит, если ждать дольше `notifyAfterMinutes` или
  автоповтора нет. Предлагается другая модель или другой сервис с запасом.
  `bb limit stuck` показывает такие треды. Если тред передан через
  `bb handoff`, плагин удаляет его строку автоповтора, чтобы два агента не
  делали одно и то же.
- **Инструмент `limit_status`** и команды:
  `bb limit status|stuck|snapshot|snapshots|restore`.

## Выключатели

- Файл `.bb/hands-off` в папке: снимки и подтягивание её не трогают.
- Настройки: `snapshots` (`push-private` / `local` / `off`), `steer`,
  `onLimit` (`suggest` / `off`), пороги `shortEconomy`, `shortFinish`,
  `longEconomy`, `longFinish`, `etaEconomy`, `etaFinish`,
  `notifyAfterMinutes`, `timeZone`. Пример:
  `bb plugin config limit-guard set snapshots local`.
- Полностью: `bb plugin disable limit-guard`.

## Продолжить с другой машины или копии

`bb limit snapshots` показывает снимки. `bb limit restore --from <окружение>
[--thread <id>]` раскладывает снимок как незакоммиченные правки, но только в
чистой папке на той же базе. Иначе подскажет взять отдельную копию от базы.
Теневой снимок папки без git смотрится через
`git --git-dir=<dataDir>/shadow/<hash>.git log refs/heads/snapshots`.

## Ограничения

- Цифры лимита — аккаунта машины треда. При пуле аккаунтов или отдельной
  авторизации треда они могут быть чужими; при включённом пуле вывод
  предупреждает.
- Сообщение в ход отправляется, только пока ход идёт: новый ход ради него не
  начинается.
- Снимки публичных репозиториев (например, этого) не покидают машину.
- Плагин не коммитит в ветки, не делает push веток, не переносит тред сам и
  не удаляет ничего, кроме своей устаревшей ссылки на снимок.

## Установка и обновление

```sh
cd plugins/limit-guard
npm ci
npm test            # логика и снимки на временных git-репозиториях
npm run typecheck
bb plugin build .
bb plugin install . --yes      # на сервере BB
```

После правки установленной копии: `bb plugin build . && bb plugin reload limit-guard`.
Удаление: `bb plugin uninstall limit-guard`.
Проверка: `bb limit status --thread <id>`, `bb limit snapshot --thread <id>`,
`bb limit snapshots`.
