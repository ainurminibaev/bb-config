# Config Updates

Сообщает о новых стабильных релизах репозитория доработок BB и запускает их
применение агентом. Сам плагин ничего не устанавливает.

## Команды

```sh
bb config-updates status [--json]   # последний результат, без сети
bb config-updates check [--json]    # проверить GitHub сейчас
bb config-updates start             # создать тред сразу, с моделью проекта по умолчанию
```

Код выхода 1 у `status`/`check` означает **ошибку проверки** (сеть, лимит
GitHub, нет журнала). Не сообщай при этом, что обновлений нет.

При доступном релизе BB показывает уведомление «Обновить с ИИ» (не чаще
раза в сутки на версию в этом браузере). Описание релиза, установленная
версия и ручная проверка доступны в разделе «Обновления доработок» в настройках
плагина. Проверка по расписанию — каждые шесть часов.

## Как это устроено

- Учитываются только опубликованные релизы `vX.Y.Z`; draft, prerelease и
  коммиты `main` не считаются.
- Установленная версия берётся из журнала `scripts/updates.py status`, а не из
  checkout или тега.
- Кнопка «Обновить до … с ИИ» закрепляет тег и SHA и открывает штатный экран
  нового треда: задание вписано, выбраны проект этого checkout и машина
  сервера; провайдера, модель и права выбирает пользователь. `start` создаёт
  тред сразу с умолчаниями проекта. При открытом запуске в журнале обе ведут в
  его тред: второго параллельного обновления не будет.
- Плагину нужен `scripts/updates.py` рядом с исходниками. После обновления BB
  использует исходники из `.local/updates/releases/<sha>`, а журнал и проект
  относятся к исходной установке. Настройка `repository` (owner/repo) нужна
  только если `origin` checkout не ведёт на GitHub.

- После полностью применённого релиза тред, записанный в журнале как
  исполнитель обновления, архивируется сам, когда агент закончил ответ (настройка `archiveWhenDone`, по умолчанию включена).
  При остатке шагов или открытом запуске тред остаётся.

- Релиз, которому на этой установке нечего делать, принимается при проверке
  без агента (`scripts/updates.py accept`, настройка `autoAccept`). В настройках
  он помечен «принято автоматически». Незавершённые шаги и несовместимые
  зависимости тоже видны в настройках и CLI.

## Применение обновления

Пользователь обычно нажимает «Обновить» (Config Updates 0.3.0+): окно с новыми
компонентами (галочки), затем плагин сам запускает `updates.py apply` отдельным
процессом; итог, `attention` и ошибки — в настройках плагина и в
`bb config-updates status`. Агента зовут кнопкой «Разобраться с ИИ» при ошибке
или остатке: тогда разбери итог (`.local/updates/journal.json`, запись шага
`bundle`) и повтори ту же команду. Предупреждение «не проверено» значит, что
внешний плагин новее версии `tested` в `config/bundle.json`: обновление не
блокируется, сообщи пользователю, какие компоненты могут работать неправильно.

Порядок обязателен и описан в `docs/updates.md` закреплённого коммита. Обычный
путь — одно действие из папки скрипта:
`python3 scripts/updates.py apply vX.Y.Z --commit <sha> --repository <owner/repo>`
(без тега — последний релиз; так же ставится чистая машина). Оно скачивает
релиз, первым шагом `bundle` сводит установку к набору `config/bundle.json`
(ставит недостающее, обновляет старое, сохраняет исключённое и отключённое),
проверяет шаги пропущенных релизов и закрывает запуск. Повтор доделывает
остаток. Пункты `attention` (личные входы, настройки, другие машины) сообщи
пользователю явно. Отказ от компонента: `python3 scripts/bundle.py exclude <id>`.
По отдельности: `fetch` → `begin` → `run`/`record` → `finish` (шаги на других
машинах, ручные шаги) → `bb config-updates check`. Не применяй
`scripts/restore.py`, не используй `main`, не помечай шаг выполненным без проверки.

`fetch` возвращает служебный `checkout`. Исходники и инструкции берутся из этой
копии релиза. Для первого перехода со старого скрипта см. `docs/updates.md`,
раздел «Переход со старого Config Updates». `bb config-updates check` также
показывает несовместимые зависимости, изменившиеся после установки.

## Диагностика

- Если `bb plugin source config-updates` указывает на `preserved-source`, а
  проверка не находит `scripts/updates.py`, подключите постоянный checkout
  на машине сервера как проект BB. Из корня checkout выполните
  `npm --prefix plugins/config-updates ci --include=dev`,
  `bb plugin build plugins/config-updates`,
  `bb plugin install path:"$PWD/plugins/config-updates"`, затем
  `bb config-updates check`. Установка из нового пути сохраняет настройки.

- «Версия не определена» — журнала нет. Это допустимо: каждый шаг проверяется
  по фактическому состоянию. Для установки сразу из релиза — `baseline`.
- «Добавьте каталог … как проект BB» — checkout не подключён к BB как проект.
- «Another update run is open» — см. `python3 scripts/updates.py status`,
  проверь тред-владельца; `begin … --takeover` только если он точно остановлен.
- Остаток после частичного применения виден в `status` (`partial.remaining`).
