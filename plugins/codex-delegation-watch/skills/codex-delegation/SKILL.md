# Делегирование в Codex: цель первой, надзор до завершения

Правило владельца для всего BB: любой тред, который создаёт подтред или тред в
другом проекте на провайдере Codex (через `bb thread spawn`, Telegram
spawnDelegated/sendDelegated, workflow или плагин), ставит ребёнку цель
(Goal) первой и не теряет его из виду, пока цель не выполнена.

## 1. Цель первой

Первая строка первого сообщения ребёнку — цель, подробности ниже:

```
/goal <конечный результат одной-двумя фразами и критерий готовности>

<подробное поручение, границы доступа, что вернуть>
```

Как это работает в BB (проверено 18.11.2026, BB 0.49.0, Codex CLI 0.170):

- Цель Codex создаёт сама модель инструментом `create_goal`, когда её явно
  просят. BB не разбирает `/goal <текст>` (только `/goal resume|pause|clear`),
  поэтому строка `/goal …` — это явная просьба модели, а не команда клиента.
- По этой же причине цель можно поставить и сообщением в уже работающий ход
  (`bb thread tell`): «Поставь цель треда: вызови create_goal с objective …».
  Не работает в работающем ходе только `/goal resume|pause|clear`.
- Цель поставлена, если в ленте треда есть событие
  `thread/extensionState/updated` с `kind = provider-codex/goal`; проще —
  `bb codex-watch check <тред>` (строка «Цель»). Ответ модели «цель
  поставлена» доказательством не считается.

Отдельную очередь (`--mode queue`) для поручения после `/goal` не используйте:
одно сообщение с целью в первой строке надёжнее и не создаёт лишний ход.

## 2. Надзор — автоматический

Плагин Codex Delegation Watch сам ставит под надзор каждый видимый тред Codex с
родителем, созданный после установки плагина (если надзор и автоподключение
включены в настройках). Ничего запускать не нужно.

- Первая проверка через 2 минуты после создания, затем каждые 5 минут.
- Нет цели через 90 с работы — ребёнку уходит просьба вызвать `create_goal`.
- Ход закончился, а цель активна, на двух проверках подряд — просьба
  продолжить или задать один конкретный вопрос.
- Вопрос или разрешение ребёнка, ошибка без повтора в очереди, цель
  `blocked`/`paused`/лимит, 15 минут без событий в работающем ходе —
  сообщение родителю `[Надзор Codex] …` (каждая проблема — один раз).
- Не больше 3 подталкиваний на тред; дальше — одно сообщение родителю,
  и надзор переходит в режим наблюдения.
- Цель `complete`, тред в архиве или удалён — надзор снимается сам
  (максимум через 3 дня в любом случае).
- При норме ничего не пишет. «Уход не в ту сторону» по смыслу плагин не
  оценивает: это делает родитель, читая отчёты ребёнка о ходах.

Родитель, получив `[Надзор Codex]`, разбирается сам: отвечает ребёнку в рамках
поручения, корректирует курс или спрашивает владельца. Не отвечай на такое
сообщение пустым подтверждением.

## Настройки и выключение

Settings → Installed plugins → Codex Delegation Watch или `bb codex-watch config
get|set <ключ> <значение>`: `enabled` (надзор включён), `autoEnroll`
(подключать новых Codex-детей), `defaultMode` (`supervise` — с подталкиванием,
`observe` — только наблюдать и сообщать), `intervalMinutes` (1–60, по умолчанию
5), `maxNudges` (0–10, по умолчанию 3), `checkGoal` (проверять постановку
цели). Числа выше в описании надзора — значения по умолчанию.

Выключение (`config set enabled false`) только останавливает проверки и
подталкивания: треды работают как обычно, список надзора сохраняется. Если
надзор выключен, сам следи за ребёнком после делегирования. Меняй настройки
только по просьбе владельца.

## Команды

- `bb codex-watch status [--all] [--json]` — треды под надзором и итог последней проверки.
- `bb codex-watch check <тред> [--json]` — проверить сейчас без действий: статус, цель, вопросы, решение надзора. Работает для любого треда Codex.
- `bb codex-watch add <тред> [--observe]` — поставить под надзор старый тред (созданный до плагина или без родителя). `--observe` — только записывать, ничего не писать ни ребёнку, ни родителю.
- `bb codex-watch remove <тред>` — снять с надзора.
- `bb codex-watch mode <тред> supervise|observe` — сменить режим треда.
- `bb codex-watch config get [ключ]`, `config set <ключ> <значение>` — настройки.
- `bb codex-watch resume-goal <тред>` — возобновить остановленную цель (`/goal resume` от имени BB). Только когда тред не работает. Сообщение агента `bb thread tell … "/goal resume"` для этого не годится: BB добавляет к нему подпись отправителя, и Codex читает его как обычный текст.

Скрытые фоновые треды плагинов (`visibility: hidden`) автоматически не
подключаются; при необходимости — `bb codex-watch add`. Тред без родителя
(или потерявший родителя) только наблюдается: писать о проблемах некому,
поэтому надзор ничего не отправляет ни в него, ни наружу. Тред, с которого
надзор уже снят (цель выполнена), при новом поручении с новой целью поставь
под надзор снова: `bb codex-watch add <тред>`.
