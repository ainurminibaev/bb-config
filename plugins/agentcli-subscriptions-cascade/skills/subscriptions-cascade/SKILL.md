# Каскад подписок

Плагин ведёт один тред по ступеням «машина × провайдер (CLI) × аккаунт».
Ход идёт на первой ступени, у которой есть лимит. Порядок ступеней задаёт
владелец. Ход исполняется своим провайдером «Каскад» (импортированный штатный
мост Claude Code, запуск CLI на машине ступени, синхронизация Mutagen). Пустые
настройки — каскад по умолчанию готов к работе (`executionMode: provider`);
«Выключено» — явный выбор владельца. Переход Claude ↔ Codex внутри треда и
карточка подтверждения в ходе — в разработке: ступень с подтверждением пока
отклоняет ход с причиной.

## Где настраивается

Настройки → Плагины → «Каскад подписок». Экран устроен от главного к редкому;
подробности раскрываются по щелчку, пояснения — во всплывающих «?».

- **Сводка** сверху: «Сейчас ход пошёл бы на: Opus · vclaude Mac» для профиля
  по умолчанию, цепочка включённых ступеней с цветом лимита (зелёный — есть,
  красный — исчерпан, жёлтый — неизвестен) и кнопка «Изменить порядок»: она
  показывает стрелки ↑/↓ у ступеней и ставит фокус на первую ручку.
- **Ступени** — одна строка на ступень: машина, CLI, аккаунт, полоска остатка
  и короткая строка лимита («неделя 51 %», «исчерпан до 01.12 21:00»,
  «380,73 из 405 млн» у пакета vclaude), выключатель, ручка ⋮⋮ (перетаскивание
  мышью или стрелками с клавиатуры). Метка «спросит» — ступень с подтверждением.
  За «⋯» — подпись аккаунта, «Подписка» или «API-шлюз» (нативный CLI через
  `ANTHROPIC_BASE_URL`, полноправная ступень), источник квоты («Штатно (BB)»
  или «Пакет vclaude»), что делать при неизвестной квоте и «Спрашивать перед
  входом» (профиль может переопределить). Точка под «⋯» — параметры отличаются
  от умолчаний.
- **Профили** — пункты списка моделей провайдера «Каскад», в порядке строк;
  первый включённый — по умолчанию (метка «по умолчанию»). Строка: ручка,
  выключатель, имя, подпись «Старт: …» и «i». Из коробки: «Авто», «Авто · без
  Codex», «Opus → Авто», «Fable → Авто», «Только Opus 5.5», «Только Fable 5.2».
  Щелчок по имени раскрывает карточку:
  - название и полная подпись (та же строка видна в списке моделей);
  - «Модели» — три кнопки: «Только» (только X), «Сначала → потом Авто»
    (X на всех ступенях, когда X нигде нет — любые), «Авто» (на каждой ступени
    лучшая модель по приоритету); модель — из таблицы;
  - «Ступени» — чипы: перетаскивание задаёт свой порядок, щелчок исключает
    ступень, «?» включает или выключает подтверждение в этом профиле;
    «сбросить к общему» возвращает общий порядок. Чипы провайдеров исключают
    провайдера целиком («без Codex»);
  - превью «сейчас ход пошёл бы на: …» по текущим лимитам; «Дублировать», «Удалить».
  - «i» — схема каскада: попытки слева направо, лимит цветом, «ход сейчас»,
    исключённые — серые перечёркнутые. Схема строится тем же движком, что
    выбирает ступень. В штатном списке моделей «i» нет: SDK не даёт кнопок у
    пунктов, только подпись.
  - «+ Профиль»: «Только модель», «Модель → Авто», «Без Codex».
- Свёрнутые секции; в заголовке — резюме, «!» — нужна правка:
  - **Машины** («3 готовы», «1 не на связи из 3») — вкл./выкл., имя, общий
    путь (по умолчанию `/opt/bbfs`), опора (эталон файлов), «настроено N/4»
    (щелчок — команды мастера). Кнопки «Настроить машины» (мастер),
    «Предпросмотр шагов» (только план), «Обновить обнаружение» (перечитать
    CLI, модели и лимиты), «Добавить найденное» (новые машины — выключенными,
    новые ступени — в конец каскада с подтверждением).
  - **Модели** («6 несопоставленных») — приоритет для «Авто» (чипы
    перетаскиваются) и таблица: строка — модель, столбец — машина, в ячейке
    ID модели у CLI. Подсвеченная ячейка «не найдено» — укажите ID или
    очистите (модель не участвует на этой машине); «авто» возвращает автоподбор.
  - **Машины** — у каждой машины, кроме опоры, поле «SSH к опоре»: имя из
    `~/.ssh/config` этой машины или `user@host`, нужно Mutagen. Пустое — берётся
    прежнее значение из RPC `syncSetAnchorSsh`. Ошибка «не задан SSH-доступ»
    говорит, где его задать.
  - **Файлы** — синхронизация «По требованию» (lazy) или «Постоянно» (warm),
    по умолчанию и по проекту; `.env`; что не синхронизировать. Синхронизируется
    всё, кроме этих исключений: `.gitignore` правилом синхронизации не считается.
    Все машины POSIX — symlink как есть (`posix-raw`, абсолютные тоже); есть
    нативный Windows — `portable` с предупреждением. Ошибки сканирования
    отдельных путей ход не блокируют: в строке синхронизации «не
    синхронизировано путей — N»; блокируют конфликт и ошибка записи.
  - **Дополнительно** («по умолчанию» / «изменено: N») — возврат на ступень
    выше через N минут (30, только между ходами), ожидание сброса до N часов
    (6, потом вопрос владельцу), порог остатка, свежесть показания, режим
    исполнения, подтреды на чужих машинах. Изменённое поле помечено точкой.
    Здесь же **тестовая квота** для приёмочных сценариев S1–S13: лимит каждой
    ступени вручную, только в тредах из списка; пока она включена, превью и
    схемы считаются по ней, а резюме секции предупреждает. После приёмки выключите.
- Панель «Сохранить» появляется внизу, только когда есть несохранённые изменения.

Конфигурация хранится в настройке плагина `config` (JSON):
`bb plugin config agentcli-subscriptions-cascade`. Правьте её через экран.
Пустое значение означает каскад по умолчанию: Claude на Tru → Claude на Mac
через шлюз vclaude → Claude Pro на UA → Codex на Mac и UA с подтверждением.
Машины находятся по имени («Tru», «UA») и платформе (macOS — Mac). Если в
сохранённой конфигурации нет поля `profiles`, профили из коробки добавляются
автоматически; пустой список, оставленный владельцем, не заполняется.

## Почему ступень пропускается

- «квота неизвестна: …»:
  - «нет входа или нет доступа к квоте» — у подписки нет данных;
  - «источник лимитов не поддерживается (шлюз?)» — ступень через шлюз;
  - «данные устарели» — показанию больше 60 с.

  При `onUnknown: skip` ступень пропускается, при `try` идёт в ход.
- Claude на Mac работает через API-шлюз, поэтому usageLimits отдаёт
  `unauthenticated` — это не ошибка входа. Для vclaude остаток берётся у
  плагина `thread-account-usage` (RPC `vclaude`) в единицах пакета: «осталось
  N млн из M млн ед., до <дата>». Если плагина нет, квота неизвестна.
- Модель без ID на машине не участвует в каскаде этой машины (на схеме —
  «нет модели»). Например, на UA (Pro) нет Fable: «Только Fable» идёт Tru → Mac.
- Ступень исключена в профиле — серая и перечёркнутая на схеме.
- «Только X» при исчерпанной X ждёт сброса и в «Авто» не уходит.
- Включён тестовый источник квоты, и тред в списке тестовых.
- Подтред без разрешения не уходит с машины родителя.

## Исполнитель хода и команды

- Режим исполнения «Свой провайдер» (`policies.executionMode: provider`, по
  умолчанию) включает ходы. В режиме `off` тред на «Каскаде» отвечает подсказкой.
- Список моделей провайдера не бывает пустым: до обнаружения машин видны
  профили с подписью «ступени ещё не найдены» (`bb provider models subscriptions-cascade`).
- **Тестовая квота одного треда** (сценарии S1–S17, реальные лимиты не тратятся):
  `bb subscriptions-cascade test-quota --thread <id> --set 'Tru=exhausted,+30m;Mac:claude=ok'`.
  Ступень — ID, «Машина[:claude|codex]» или подпись; состояние `exhausted|ok|unknown|unavailable`;
  сброс — ISO или `+30m`/`+2h` (после сброса исчерпание считается «лимит есть»).
  Без `--set` — показать, `--clear` — снять. То же — RPC `testQuota`. Общий флаг не нужен.
- Сервер каскада не ответил перед ходом — ход не запускается (код 75, строка в
  ленте), штатный CLI машины моста не подменяет каскад. Повторите ход; проверьте
  `bb plugin list`.
- Ход, упавший до запуска CLI, сессию не создаёт: следующий ход стартует с тем же
  ID через `--session-id`, а не `--resume`.
- Сбои без лимита (529, 5xx, сеть) повторяет штатный provider-retry, как у Claude;
  ступень не меняется. При лимите provider-retry спрашивает каскад
  (`provider-retry.v1.availability`): есть свободная ступень — повтор сразу на ней.
- Остановка хода гасит CLI и на чужой машине (SIGTERM через терминал BB).
- Переход Claude → Codex после «Да» в карточке, «модель недоступна на тарифе»
  и обновление плагина во время подготовки повторяются штатным автоповтором BB
  (provider-retry, обычно 5–60 с) — писать сообщение заново не нужно. Ячейка
  модели, недоступной на аккаунте машины, в таблице помечена с причиной на сутки.
  «Недоступна» — это и «requires usage credits» у Claude Pro, и отказ шлюза
  vclaude «API Error: 402 … доступен только в тарифе …» (с 0.2.16).
- Codex на ступени каскада получает ровно ту песочницу и сеть, что штатный тред
  Codex (параметры моста BB не меняются, с 0.3.0); меняются только пути проекта
  на путь ступени `/opt/bbfs/<проект>…`. До 0.3.0 песочница была строже
  (`workspace-write` без сети), и `bb thread messages` из сводки там не работал.
- Пока ход готовится, строка перехода обновляется на месте: «Подготовка Mac:
  передача · синхронизация Tru → Mac · 2 341 / 10 520 файлов · 22 % · 0:47».
  Сбой шага — до 3 попыток, затем следующая ступень; конфликт файлов — отказ.
  Отказ читается «Ход не запущен: Каскад подписок → <источник>: <причина>» и
  строкой «Что сделать».
- Единица синхронизации — рабочая папка треда (cwd на опоре): worktree треда
  получает свою папку `/opt/bbfs/<проект>-w<хеш>` и свою блокировку «один
  писатель». Машина треда неизвестна — отказ; папка проекта не подставляется.
  Блокировка упавшего, заархивированного или удалённого треда снимается сама.
- **Уборка реплик** `bb subscriptions-cascade gc [--dry-run] [--machine <id|имя>] [--json]`:
  для единиц синхронизации без живого треда (все архивированы или удалены)
  завершает сессии Mutagen `bbcascade=1` и удаляет реплику
  `/opt/bbfs/<проект>-w<хеш>` на машинах-исполнителях. Опору (worktree на
  машине моста, bind mount) не трогает никогда; на опоре команда отказывается.
  Не трогает единицу с живым тредом, с живой блокировкой писателя и с идущим
  ходом. Изменения после последнего хода (или всё дерево, если снимка нет)
  сначала копируются в `~/bbfs-quarantine/<реплика>/<время>-gc` на той же машине,
  со списком удалённых файлов. Неизвестные реплики только показываются.
  Сначала запускай с `--dry-run`. Автоматически: через минуту после архивации
  или удаления треда каскада и раз в сутки; выключить —
  `files.autoGc: false` в настройках.
- Приёмка S13 без правки BB: `bb subscriptions-cascade test-bridge --incompatible`
  (снять — `--compatible`).
- `bb subscriptions-cascade status --thread <id> --json` — паспорт треда:
  текущая ступень (машина, CLI, модель, аккаунт), опора, режим синхронизации,
  где свежая копия файлов. Другие плагины читают то же через RPC `threadStatus`.
- `bb subscriptions-cascade adopt --stuck|--thread <id>|--project <id> [--dry-run]`
  — перевести треды штатных Claude Code/Codex в каскад через Handoff и снять у
  исходных автоповтор provider-retry. Сначала запускай с `--dry-run`. С той же
  сессией Claude — `adopt --native` (раздел ниже).
- Ход отклонён с текстом «Штатный мост … ещё не появился на этой машине» —
  запусти один короткий ход штатного Claude Code на машине треда и повтори.
- Журнал запускателя: `<dataDir моста>/launcher/launcher.log` на машине треда
  (какая ступень, терминал на чужой машине, возврат файла сессии, `confirm …`).
- Ступень с подтверждением показывает карточку над полем ввода прямо в ходе:
  «Да» (на этот ход / в треде до сброса / всегда), «Ждать» (ход не идёт до
  сброса прежней ступени), «Пропустить» (следующая ступень), «Отменить». Пока
  карточка открыта, ход ждёт. «Всегда» — правило проекта, действует и в
  других тредах.
- Переход Claude ↔ Codex идёт внутри того же треда. У каждого провайдера своя
  сессия. Первый переход — сводка треда с подсказкой
  `bb thread messages <тред> --json --after-seq N`; возврат — прежняя сессия
  плюс события после неё. Если прежней сессии нет — новая со сводкой и строка
  в ленте. Состояние: RPC `nativeSessions` (`{outerId, active, sessions}`).
  Каждая смена ступени (машина, провайдер, аккаунт) даёт строку перехода; возврат
  читается «Лимит сброшен → Mac · Claude ← Codex». Строки нет — смотри журнал
  моста (`switch … → …`) и версию плагина (до 0.2.13 возврат на Claude строку терял).
- Опоздавшие записи машины (изменения после её прошлого хода) не попадают на
  опору: перед ходом они копируются в `~/bbfs-quarantine/<реплика>/<время>/`, а в
  ленте — отдельная строка «Синхронизация: Отложено файлов Mac: N изменённых,
  M удалённых — <путь>». Ход идёт дальше. До 0.2.14 эта строка пряталась в
  подробностях успешного flush и не была видна.

## Если ты сам на каскаде

Тред каскада узнаёт о себе из окружения CLI ступени, а не из промпта (начало
запроса неизменно — кэш промптов не теряется):

- `BB_CASCADE_PROFILE` — профиль треда (`auto`, `auto-no-codex`, `pin:…`);
- `BB_CASCADE_STEP` — ступень этого хода (`<машина>:<cli>:*`).

Машина и аккаунт могут меняться между ходами — это нормально; провайдера сам
не переключай и handoff сам не делай. Паспорт: `bb subscriptions-cascade status --json`.
На чужой ступени (Mac, UA) CLI видит свой тред так же, как штатный: `BB_THREAD_ID`,
`BB_PROJECT_ID`, `BB_ENVIRONMENT_ID` приходят с машины треда, `BB_SERVER_URL` и
`BB_CLI` — свои у машины ступени, `BB_THREAD_STORAGE` — папка этой машины
(`<данные BB>/thread-storage/<тред>`; её файлы на опору не уезжают). `bb status`
и `bb thread show "$BB_THREAD_ID"` работают и там (с 0.3.0).

## Запуск подтредов

Тред на каскаде запускает подтреды тоже через каскад:

1. В окружении есть `BB_CASCADE_PROFILE` — подтред с тем же профилем:
   `bb thread spawn --parent-self --provider subscriptions-cascade --model "$BB_CASCADE_PROFILE" --prompt …`
   (кавычки обязательны: ID `pin:…` содержит `*`).
2. Владелец попросил конкретное («Codex 6.2 на Tru», «на аккаунте vclaude», «Opus на UA») —
   сначала `bb subscriptions-cascade resolve "<просьба дословно>" --json`:
   - `{"match":{"profileId","label"}}` — `--provider subscriptions-cascade --model '<profileId>'`;
   - `{"candidates":[…]}` — несколько ступеней: спроси владельца, какую (метки `label`);
   - `{"fallback":{"provider","machine","model","reason","nearest"}}` — такой ступени в
     каскаде нет (аккаунт не подключён, машины нет, ступень выключена, модели нет в
     таблице): запусти штатным провайдером `--provider <provider> [--machine <machine>]
     [--model <model>]` и одной строкой в ответе владельцу: «запущен мимо каскада:
     <reason>; лимиты не переключаются». `provider: null` — просьба не разобрана, спроси.
     `nearest` — ближайшие ступени каскада, их можно предложить.
   `resolve` только читает настройки и таблицу моделей, модели не вызывает.
3. Каскада нет (провайдер `subscriptions-cascade` не установлен, режим «Выключено») —
   штатный провайдер, та же строка предупреждения.

## Закреплённые ступени

В списке моделей «Каскада» после профилей идут закреплённые ступени:
«Tru · Claude (Max 20)», «Tru · Claude (Max 20) · Opus 5.5», «Mac · Claude (vclaude) · Fable 5.2»,
«UA · Codex» … ID — `pin:<stepId>` (модели по приоритету, только эта ступень) или
`pin:<stepId>:<ключ модели>` (только эта модель на ней). Список строится из включённых
ступеней и таблицы моделей; модели без ID на машине, недоступные на аккаунте, ступени
выключенные или без CLI не показываются. Выбор модели BB 0.50.1 групп и вложенности не
умеет — список плоский (с поиском), не больше 64 пунктов.

- Закреплённая ступень исчерпана — ход ждёт сброса или спрашивает владельца, как
  «Только X»; на другие ступени не уходит.
- Подтверждение входа («спросит», Codex) на закреплённую ступень не спрашивается:
  владелец выбрал её сам. Запрет «подтред только на машине родителя» на неё тоже не действует.
- Сменил модель треда на «Авто» — работа продолжается с той же сессией и файлами,
  как при обычном переходе каскада (возврат на ступень выше — не раньше N минут).

## Одновременные ходы и рабочая папка

- **Лимит ходов на ступени** (⋯ ступени → «Одновременных ходов», `maxConcurrent`;
  по умолчанию без лимита). Считаются ходы всех тредов и подтредов. Достигнут —
  «Ступень занята»: «Ждать места» (`onBusy: wait`, строка «Жду: на <машина> уже N
  ход(ов)», до 30 мин, потом отказ с повтором) или «Следующая ступень» (`next`, дальше
  по профилю). Счёт в памяти сервера: после перезагрузки плагина начинается заново,
  ход без завершения перестаёт считаться через 3 ч.
- **Рабочая папка** (несколько тредов одной папки):
  - треды на одной машине пишут одновременно, как в штатном BB: первый писатель
    выравнивает реплику по опоре и делает карантин опоздавших, следующие входят без
    этого (карантин забрал бы незаконченную запись соседа); конец хода любого треда —
    его правки уходят на Tru (flush W), пауза сессий и снимок — когда уходит последний;
  - ход на опоре (Tru) при писателе на исполнителе не ждёт, и наоборот: обе стороны
    пишут через двустороннюю синхронизацию (two-way-safe), строка «… пишут рабочую
    папку одновременно»; конфликт одного файла — по правилам two-way-safe и карантину;
  - папку держит тред на другой машине-исполнителе — второй тред идёт на ту же машину,
    если она есть в его профиле и доступна; иначе ждёт со строкой «Жду: папку держит тред
    «<название>» на <машина>» (до 10 мин);
  - писатель, чей тред уже не идёт (упал, архив), снимается — счётчик не залипает.
- Долгая подготовка (ожидание папки, первая синхронизация до 20 мин) не рвёт запрос
  запускателя: решение перед ходом приходит по билету (`routeTurnResult`), до 0.3.0
  запрос падал через 300 с с «fetch failed».

## Перевод треда Claude Code без потери памяти (`adopt --native`)

`bb subscriptions-cascade adopt --native --thread <id> [--model <профиль>] [--prompt <текст>] [--wait <сек>] [--dry-run] [--json]`
— для будущего диспетчера. Сначала всегда `--dry-run` (тред, окружение, ID сессии,
занят ли сейчас). Без `--dry-run`: ждёт простоя исходного треда (до `--wait`, 600 с),
создаёт тред каскада в том же окружении (та же папка и ветка) с тем же названием и
родителем, профиль по умолчанию `auto`; первое сообщение — `--prompt` (по умолчанию —
контрольный вопрос «что решили последним, с каким файлом работали, что осталось»).
Первый ход нового треда копирует jsonl исходной сессии Claude под ID своей сессии на
машине треда и продолжает её `--resume` — модель видит ту же цепочку сообщений.
Исходный тред не трогается (архивирует диспетчер после проверки). Только Claude Code;
Codex и ACP — обычный `adopt` (Handoff-документ). **Живые треды владельца не
переводить без его прямого «да»** (решение владельца: пока не переводим).

## Мастер «Настроить»

Мастер идёт на сервере: можно закрыть экран, при возврате — «Продолжить».
`bb subscriptions-cascade setup` (`--machine <имя>`, `--recheck` —
перепроверить, `--reset` — с нуля, `--allow-ssh` — разрешить вход на опору
по ключу, `--dry-run`). Шаг «SSH до опоры» создаёт ключ
`~/.ssh/bb_cascade_ed25519` на машине и **без разрешения владельца на опору
его не добавляет**: мастер показывает ключ и куда он будет записан. Для шага
нужен «Адрес для SSH» у опоры (Машины → опора). Алиас — `bb-<опора>`.
Выключение машины снимает её ключ с опоры. Первый ход на ненастроенную
машину сам доделывает шаги без согласия; иначе — строка «Нужно разрешение»
и ход на следующей ступени. Mutagen обновляется до версии плагина, когда на
машине нет идущих сессий каскада.

Мастер проходит включённые машины по очереди: определяет машину, создаёт папку
общего пути, ставит Mutagen и проверяет путь пробной записью через `bb file`.
Каждый шаг сначала проверяется, поэтому повтор безопасен и продолжает с места
остановки.

- На Mac папку создаёт системное окно пароля: предупредите владельца.
- На Linux под root шаг выполняется без запроса. Не под root нужен
  `sudo -n`, иначе шаг ручной: команду покажет ссылка «команды».
- На нативном Windows Mutagen ставится вручную.

Сессии синхронизации мастер не создаёт: их создаёт первый ход на машине
(нужен «SSH к опоре»).
