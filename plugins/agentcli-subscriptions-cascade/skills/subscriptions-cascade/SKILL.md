# Каскад подписок

Плагин ведёт один тред по ступеням «машина × провайдер (CLI) × аккаунт».
Ход идёт на первой ступени, у которой есть лимит. Порядок ступеней задаёт
владелец. Версия 0.1.0 — каркас: настройки, движок выбора, лимиты и мастер.
**Ходы на других машинах плагин пока не исполняет** (`executionMode: off`).

## Где настраивается

Настройки → Плагины → «Каскад подписок». Экран устроен от главного к редкому;
подробности раскрываются по щелчку, пояснения — во всплывающих «?».

- **Сводка** сверху: «Сейчас ход пошёл бы на: Opus · vclaude Mac» для профиля
  по умолчанию, цепочка включённых ступеней с цветом лимита (зелёный — есть,
  красный — исчерпан, жёлтый — неизвестен) и кнопка «Изменить порядок»: она
  показывает стрелки ↑/↓ у ступеней и ставит фокус на первую ручку.
- **Ступени** — одна строка на ступень: машина, CLI, аккаунт, полоска остатка
  и короткая строка лимита («неделя 51 %», «исчерпан до 01.12 21:00»,
  «380,73 из 405 млн» у пакета vclaude), выключатель, ручка ⋮⋮ (перетаскивание
  мышью или стрелками с клавиатуры). Метка «спросит» — ступень с подтверждением.
  За «⋯» — подпись аккаунта, «Подписка» или «API-шлюз» (нативный CLI через
  `ANTHROPIC_BASE_URL`, полноправная ступень), источник квоты («Штатно (BB)»
  или «Пакет vclaude»), что делать при неизвестной квоте и «Спрашивать перед
  входом» (профиль может переопределить). Точка под «⋯» — параметры отличаются
  от умолчаний.
- **Профили** — пункты списка моделей провайдера «Каскад», в порядке строк;
  первый включённый — по умолчанию (метка «по умолчанию»). Строка: ручка,
  выключатель, имя, подпись «Старт: …» и «i». Из коробки: «Авто», «Авто · без
  Codex», «Opus → Авто», «Fable → Авто», «Только Opus 5.5», «Только Fable 5.2».
  Щелчок по имени раскрывает карточку:
  - название и полная подпись (та же строка видна в списке моделей);
  - «Модели» — три кнопки: «Только» (только X), «Сначала → потом Авто»
    (X на всех ступенях, когда X нигде нет — любые), «Авто» (на каждой ступени
    лучшая модель по приоритету); модель — из таблицы;
  - «Ступени» — чипы: перетаскивание задаёт свой порядок, щелчок исключает
    ступень, «?» включает или выключает подтверждение в этом профиле;
    «сбросить к общему» возвращает общий порядок. Чипы провайдеров исключают
    провайдера целиком («без Codex»);
  - превью «сейчас ход пошёл бы на: …» по текущим лимитам; «Дублировать», «Удалить».
  - «i» — схема каскада: попытки слева направо, лимит цветом, «ход сейчас»,
    исключённые — серые перечёркнутые. Схема строится тем же движком, что
    выбирает ступень. В штатном списке моделей «i» нет: SDK не даёт кнопок у
    пунктов, только подпись.
  - «+ Профиль»: «Только модель», «Модель → Авто», «Без Codex».
- Свёрнутые секции; в заголовке — резюме, «!» — нужна правка:
  - **Машины** («3 готовы», «1 не на связи из 3») — вкл./выкл., имя, общий
    путь (по умолчанию `/opt/bbfs`), опора (эталон файлов), «настроено N/4»
    (щелчок — команды мастера). Кнопки «Настроить машины» (мастер),
    «Предпросмотр шагов» (только план), «Обновить обнаружение» (перечитать
    CLI, модели и лимиты), «Добавить найденное» (новые машины — выключенными,
    новые ступени — в конец каскада с подтверждением).
  - **Модели** («6 несопоставленных») — приоритет для «Авто» (чипы
    перетаскиваются) и таблица: строка — модель, столбец — машина, в ячейке
    ID модели у CLI. Подсвеченная ячейка «не найдено» — укажите ID или
    очистите (модель не участвует на этой машине); «авто» возвращает автоподбор.
  - **Файлы** — синхронизация «По требованию» (lazy) или «Постоянно» (warm),
    по умолчанию и по проекту; `.env`; что не синхронизировать.
  - **Дополнительно** («по умолчанию» / «изменено: N») — возврат на ступень
    выше через N минут (30, только между ходами), ожидание сброса до N часов
    (6, потом вопрос владельцу), порог остатка, свежесть показания, режим
    исполнения, подтреды на чужих машинах. Изменённое поле помечено точкой.
    Здесь же **тестовая квота** для приёмочных сценариев S1–S13: лимит каждой
    ступени вручную, только в тредах из списка; пока она включена, превью и
    схемы считаются по ней, а резюме секции предупреждает. После приёмки выключите.
- Панель «Сохранить» появляется внизу, только когда есть несохранённые изменения.

Конфигурация хранится в настройке плагина `config` (JSON):
`bb plugin config agentcli-subscriptions-cascade`. Правьте её через экран.
Пустое значение означает каскад по умолчанию: Claude на Tru → Claude на Mac
через шлюз vclaude → Claude Pro на UA → Codex на Mac и UA с подтверждением.
Машины находятся по имени («Tru», «UA») и платформе (macOS — Mac). Если в
сохранённой конфигурации нет поля `profiles`, профили из коробки добавляются
автоматически; пустой список, оставленный владельцем, не заполняется.

## Почему ступень пропускается

- «квота неизвестна: …»:
  - «нет входа или нет доступа к квоте» — у подписки нет данных;
  - «источник лимитов не поддерживается (шлюз?)» — ступень через шлюз;
  - «данные устарели» — показанию больше 60 с.

  При `onUnknown: skip` ступень пропускается, при `try` идёт в ход.
- Claude на Mac работает через API-шлюз, поэтому usageLimits отдаёт
  `unauthenticated` — это не ошибка входа. Для vclaude остаток берётся у
  плагина `thread-account-usage` (RPC `vclaude`) в единицах пакета: «осталось
  N млн из M млн ед., до <дата>». Если плагина нет, квота неизвестна.
- Модель без ID на машине не участвует в каскаде этой машины (на схеме —
  «нет модели»). Например, на UA (Pro) нет Fable: «Только Fable» идёт Tru → Mac.
- Ступень исключена в профиле — серая и перечёркнутая на схеме.
- «Только X» при исчерпанной X ждёт сброса и в «Авто» не уходит.
- Включён тестовый источник квоты, и тред в списке тестовых.
- Подтред без разрешения не уходит с машины родителя.

## Исполнитель хода и команды

- Режим исполнения «Свой провайдер» (`policies.executionMode: provider`) включает
  ходы. В режиме `off` тред на «Каскаде» отвечает подсказкой включить режим.
- `bb subscriptions-cascade status --thread <id> --json` — паспорт треда:
  текущая ступень (машина, CLI, модель, аккаунт), опора, режим синхронизации,
  где свежая копия файлов. Другие плагины читают то же через RPC `threadStatus`.
- `bb subscriptions-cascade adopt --stuck|--thread <id>|--project <id> [--dry-run]`
  — перевести треды штатных Claude Code/Codex в каскад через Handoff и снять у
  исходных автоповтор provider-retry. Сначала запускай с `--dry-run`.
- Ход отклонён с текстом «Штатный мост … ещё не появился на этой машине» —
  запусти один короткий ход штатного Claude Code на машине треда и повтори.
- Журнал запускателя: `<dataDir моста>/launcher/launcher.log` на машине треда
  (какая ступень, терминал на чужой машине, возврат файла сессии, `confirm …`).
- Ступень с подтверждением показывает карточку над полем ввода прямо в ходе:
  «Да» (на этот ход / в треде до сброса / всегда), «Ждать» (ход не идёт до
  сброса прежней ступени), «Пропустить» (следующая ступень), «Отменить». Пока
  карточка открыта, ход ждёт. «Всегда» — правило проекта, действует и в
  других тредах.
- Переход Claude ↔ Codex идёт внутри того же треда. У каждого провайдера своя
  сессия. Первый переход — сводка треда с подсказкой
  `bb thread messages <тред> --json --after-seq N`; возврат — прежняя сессия
  плюс события после неё. Если прежней сессии нет — новая со сводкой и строка
  в ленте. Состояние: RPC `nativeSessions` (`{outerId, active, sessions}`).

## Мастер «Настроить»

Мастер проходит включённые машины по очереди: определяет машину, создаёт папку
общего пути, ставит Mutagen и проверяет путь пробной записью через `bb file`.
Каждый шаг сначала проверяется, поэтому повтор безопасен и продолжает с места
остановки.

- На Mac папку создаёт системное окно пароля: предупредите владельца.
- На Linux под root шаг выполняется без запроса. Не под root нужен
  `sudo -n`, иначе шаг ручной: команду покажет ссылка «команды».
- На нативном Windows Mutagen ставится вручную.

Сессии синхронизации мастер не создаёт.

## Для разработки

Архитектура, этапы исполнения (путь A — relay под штатными Claude Code и
Codex; путь B — свой провайдер) и места под их реализацию описаны в
`ARCHITECTURE.md` плагина. Проверки: `npm test`, `npm run typecheck`,
`bb plugin build`. Не включайте `executionMode` до готового исполнителя.
