# Thread Spend

MIT-плагин для BB 0.49. В заголовке открытого треда кнопка «Тред / 24ч» показывает сумму доступных измерений токенов и полосы двухчасовых интервалов. По нажатию открываются разбивка и ходы. В боковой панели «Расход по тредам» есть периоды 1, 7 и 30 дней, фильтр по провайдеру и переход в разговор. Маркер кнопки для CSS — `[data-thread-spend-indicator]`.

В BB 0.49 индикатор использует компонентный слот заголовка, который BB сохранил для совместимости. Сборщик предупреждает, что слот выведен из публичных типов SDK. Если компонентного слота нет, штатное действие заголовка открывает ту же детализацию в панели плагина. В этом режиме динамическое число и график видны после открытия.

## CLI и RPC

```sh
bb thread-spend threads --days 7 --limit 25 --sort tokens
bb thread-spend threads --active --provider codex --sort time --json
bb thread-spend thread <thread-id> --days 1 --sort context --json
bb thread-spend commands --json
bb thread-spend usage-limits --json
```

`threads` по умолчанию показывает до 25 тредов за 7 дней, включая архивные. `--active` оставляет текущие состояния BB `starting` и `active`. `thread` в треде принимает его ID по умолчанию и показывает до 25 ходов за 24 часа, начиная с последних. `--days` принимает 1–30, `--limit` — 1–100. Сортировка `time` использует длительность по событиям BB, `context` — число токенов последнего доступного контекста за выбранный период, а `tokens` — сумму доступных измерений.

RPC доступны в `/api/v1/plugins/thread-spend/rpc/<method>` с обычной локальной авторизацией BB:

| Метод | Вход | Результат |
| --- | --- | --- |
| `summary` | `{threadId}` | 24-часовой итог, покрытие, 12 интервалов |
| `thread` | `{threadId, days?, limit?, sort?}` | Итог и ходы с разбивкой, временем и контекстом |
| `threads` | `{days?, limit?, sort?, active?, provider?}` | Ранжированные треды, объём выборки и ошибки чтения |
| `usage_limits` | `null` | Провайдерские окна из `bb.sdk.system.usageLimits({refresh: false})` |

Границы `from` и `to` — Unix-время в миллисекундах. Момент завершения относит ход целиком к периоду. Для незавершённого хода используется время последнего доступного события. `null` означает отсутствие измерения. `lower_bound` и знак ≥ означают, что по доступным событиям можно подтвердить лишь нижнюю оценку. `readLimited` и `listLimited` обозначают достижение предела обхода. Квоты представлены отдельно. BB 0.49 возвращает процент, время сброса и иногда расход в центах USD. Если суммы в центах нет, `cost` равен `null`. Размеры в токенах `usedTokens` и `limitTokens` равны `null`, поскольку SDK их не сообщает. Адреса аккаунтов и сообщения ошибок провайдеров отбрасываются.

## История и семантика

- Сервер читает только четыре явно запрошенных типа событий BB. Суммы использует из отчёта провайдера. Для Codex ввод уже включает чтение кэша, а вывод может включать reasoning. В Claude Code плагин добавляет к полю ввода кэш, чтобы представить весь ввод, и скрывает нулевой заполнитель reasoning. Кэш и reasoning показаны как составляющие, поэтому повторно в общий итог не входят.
- Для Claude Code берётся последний замер хода. Для Codex плагин вычисляет разницу cumulative-счётчиков только в одной сессии и при совпадении первого изменения с размером первого наблюдаемого запроса. При пробеле или сбросе берётся доступный замер и разница в пределах последнего непрерывного участка хода. Для других провайдеров отображается последний доступный замер хода с отметкой нижней оценки.
- BB очищает устаревшие [снимки токенов и контекста](https://github.com/get-bb/bb/blob/desktop-v0.49.0/docs/events-table-pruning.md). Доступные снимки, которые плагин успевает увидеть во время работы, сохраняются через SDK в отдельном SQLite-хранилище плагина BB. Сохраняются числа, метки времени и идентификаторы событий, тредов и сессий. Удалённые треды очищаются по событию BB, устаревшие снимки — при запуске и ежечасно. Хранение ограничено 30 днями и 200 000 снимков на установку. Пропуски до включения, во время остановки или при гонке с очисткой BB остаются пропусками.
- Длительность — разность отметок начала и завершения хода BB. Это измеренное прошедшее время, которое может включать ожидание. SDK не даёт отдельного источника длительности shell-команд или ожидания пользователя без чтения содержимого. Вложенные ходы с `parentToolCallId` не учитываются отдельно. Полный расход подагентов недоступен. Унаследованные события старше нового BB-треда и снимки уровня сессии при resume исключены.
- Чтение использует смещения списка и эксклюзивный курсор событий, общий предел четырёх параллельных вызовов SDK и отмену. Границы одной выборки — 5 000 позиций на состояние архива, 3 200 событий и до 3 200 сохранённых замеров на тред. Источник тредов — видимые записи SDK, включая архивные. Плагин не читает основную БД BB, провайдерские журналы, команды, сообщения и ключи. Трафик плагина ограничен локальными поверхностями BB.

## Проверка сборки

```sh
npm ci
bb plugin types --check
npm run typecheck
npm test
bb plugin build
npm run test:app
```

Тесты используют синтетические SDK-ответы. Проверка frontend-артефакта запускает официальный сборщик регистраций SDK и проверяет слоты и рендеринг через тестовый runtime. Исходники лицензированы в `LICENSE`, уведомления зависимостей приведены в `THIRD_PARTY_NOTICES`.

## Снимок до перехода

Пункт **До перехода** показывает сохранённые сводки за 1, 7 и 30 дней
на указанную дату. Текущие измерения BB отображаются отдельно. Снимок
не подставляет агрегированные числа в детализацию отдельных ходов.

При переходе в bb-config скрипт `scripts/switch_thread_spend.py --apply`
сохраняет доступные сводки прежнего плагина в
`.local/docs/thread-spend-history.json` перед отключением. Файл принадлежит
конкретной установке, игнорируется Git и доступен существующему приватному
резервному копированию bb-config. При отсутствии файла доступны текущие метрики.
